# Atlas after the pivot: the ordered programme

## Context

Atlas was built to automate Serenity's bottleneck method: find where a supply-chain bottleneck is forming, build the argument from primary filings (constraint, demand against supply, relief, control, capture, invalidation), and present a Hypothesis the owner can bet on, with the `pilot-review` skill as the yardstick. On 12 October the method pivoted, on evidence: a Claude session with Atlas's tools reads and records far better than the MiniMax role pipeline fed from a Hindsight bank holding every section of every filing (Facts 100% and 93% right against 75%; 19 of the researcher's 32 facts on the card against 8; a tenth of the tokens), and a cheap frontier judge catches twice the misstatements. v0.6.1 is live with sessions, Beliefs, Issues, the statement judge and Memory holding judged Beliefs; the closing measure took the trust gate from 29% to 9%.

What is still unordered: Memory's new home, how agents reach the tools, which agents exist and what each does, how a Hypothesis is presented to an end user, and the order of all of it. The owner's decisions (this plan): a **new memory bank for conclusions**, an **Atlas MCP server** as the tool surface, **one published photonics Hypothesis before the second theme**, and **Claude cloud routines** for scheduled agents once the method holds.

The execution authority stays `.scratch/atlas-beliefs/map.md` (extend it; do not start a new map): each phase below becomes tickets in `.scratch/atlas-beliefs/issues/` from 11 on, built by Sonnet implementers with `docs/agents/implementer-brief.md`, integrated and released by the lead with `release-atlas`, measured with `pilot-review`.

## The shape of the system after this programme

- **Substrate (Atlas, Postgres, the archive):** ledger, as-of search, Facts at spans, Beliefs, Issues, sessions, snapshots, gates, audit. Unchanged in kind; the record of everything an agent finds.
- **Tools (two MCP servers):** the Atlas MCP server (search, read, locate, record, judge, relate, belief, issue, recall, session, over the public API), the one surface for every agent's reading and recording; and the owner's TradingView MCP proxy (transcripts into the archive, news and the earnings calendar as leads, consensus and prices as estimated inputs and for settling predictions), under the recorded owner override.
- **Memory (a new Hindsight bank `atlas-beliefs`):** judged Beliefs and the Facts they cite, one scope per theme; what Atlas believes, recalled across sessions and themes. The old bank is a legacy index, then retired.
- **Agents (Claude sessions with the `atlas-research` skill, by hand then as cloud routines):** four roles, each a prompt over the same tools: the *Scout* finds where bottlenecks may be forming and opens Issues; the *Researcher* works an Issue into Facts and Beliefs; the *Skeptic* tries to break a Belief; the *Editor* writes the Hypothesis from proven Beliefs. The MiniMax pipeline stays the bulk mode.
- **Presentation (the website):** the Hypothesis page as the end-user product: thesis, the six steps with their Beliefs, every quote at its span, counterevidence and falsifiers, what is open; the theme page as the overview; a "what changed" feed from flags.

## Phase B: Atlas as a toolset for agents

6. **Ticket 15, the Atlas MCP server** (`backend/atlas/mcp/`, `uv run atlas mcp` and a route under the API behind the internal gateway; the `mcp` Python SDK or a thin streamable-HTTP implementation like `atlas.tradingview.mcp` in reverse): the tools of `atlas_tools.py`, each a typed MCP tool over the existing routes (no logic of its own), with the as-of rules enforced server-side (a `read` after the session's as-of is refused). The skill's text stays the method; `atlas_tools.py` becomes a thin client or is retired. Verify: a Claude Code session with the MCP server configured runs question 2 without the script; the tool list and one call tested at the HTTP seam.
7. **Ticket 16, the four agent prompts** (`.claude/skills/atlas-research/` gains `scout.md`, `skeptic.md`, `editor.md` beside the researcher's SKILL.md): the Scout reads the archive's newest documents for a theme (calls and filings of the last quarter) for bottleneck cues (allocation, sold out, lead times, permits, "two players", capacity ramps) and opens `question` Issues with the cue quoted; the Skeptic takes a proven Belief, searches for what would falsify it, records counterevidence Facts, relates them, and proposes a supersession or a flag; the Editor drafts the Hypothesis from a theme's proven Beliefs through ticket 14's job. Verify each on photonics by hand, scored where the pilot's procedure applies (the Skeptic's Facts blind-reviewed; the Scout's Issues judged on-question by the lead).
8. **Ticket 16b, the TradingView MCP server as an agent tool** (the owner's proxy in the cluster exposes 26 tools; Atlas calls three; `docs/decisions.md`, "Owner override: TradingView as a source"): the agents reach the proxy directly as a second MCP server beside Atlas's. Rules first, in `docs/decisions.md`, recorded by the owner: the transcripts and documents stay Tier B Source Versions through Atlas's ingest (the Researcher cites them as Facts at spans, never from the MCP answer); news, the earnings calendar and consensus are leads and `estimated` scenario inputs, never Evidence; price history (`mcp-tv-get-ohlcv`) is for settling predictions (ticket 19) and the early-signal replays, never for a Belief; everything the agents use from it records the override. Then the skill's agent prompts name the tools each may call: the Scout the news and calendar (what moved, what reports next week), the Editor consensus and price as the "what the market expects" paragraph of a Hypothesis, the settlement job the price history. Verify: one Scout run with TradingView leads; one Hypothesis with the market-expectations paragraph sourced to the proxy and labelled estimated.
9. **Ticket 17, scheduled routines** (Claude cloud routines, `/schedule`): weekly Scout per theme; a Researcher on `issues/next` per theme; a Skeptic on the oldest proven Belief not challenged in 30 days; every output waits for the lead's judgement (nothing is judged by a routine). Verify: two weeks of routines logged, the lead's review time per week measured.

## What is deliberately not in this programme

- Replacing Hindsight; a trackinizer fork (the owner's projection stays the owner's).
- Automated judgement of Beliefs; portfolio sizing; price data; return measurement.
- A third theme before the second has a published Hypothesis.
