# 07: The Financial Analyst received no XBRL figure

**What to build:** In pilot investigation 1's re-run (0.2.3), every scenario input the Financial Analyst proposed for Lumentum and Coherent is `missing` with the reason "No XBRL figure supplied", although both companies' companyfacts are normalized in production (`GET /api/v1/companies/{id}/financials?as_of=` returns figures). **Diagnosis (from production):** the Analyst's request carried `figures: []` for both companies because production has **no financial observation at all**: `GET /companies/{id}/financials` returns no figures, `financial-observations` is empty, and `atlas_financial_normalizations_total` is 0 for both outcomes. Both companies have an `xbrl_companyfacts` Source Document (e.g. Lumentum's `931c7ac1-de20-4518-b020-2215fd3458a2`), recorded before Phase 5's normalization existed. `EdgarAdapter.updates()` lists companyfacts only when new filings are selected, and `ingest` normalizes only a companyfacts version that this run's fetch returned; so an already-recorded, never-normalized companyfacts version is never normalized by later ingests. Fix: (1) every `ingest` (discover and updates) normalizes the company's latest companyfacts Source Version when it isn't normalized, whether or not this run fetched it; (2) `updates()` always lists companyfacts (a conditional request, cheap); (3) `uv run atlas financials normalize [--company slug]` normalizes what is pending, for the production backfill (idempotent, audited like the ingest path); document it in the runbook. Then, separately, check whether the Analyst's context (`scenarios/analyst.py`) selected figures as of the investigation's `as_of`, sent them under the metric names the prompt expects, or dropped them (currency, unit or period filters); role call `2150b97c-19db-4868-b9b4-860e3616da0a`. Fix so that reported revenue, operating margin, cash, debt and diluted shares arrive as `sourced` inputs when the observations exist.
