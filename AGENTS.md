# Atlas Research: agent guide

Evidence-driven investment research platform built around Hindsight. Start with `START_HERE.md`; the authoritative spec is `hindsight_investment_research_build_plan.md` (v1.1).

**Current effort:** the pilot review. Orient at its map, `.scratch/atlas-pilot-review/map.md`, before choosing work: take the first open, unblocked ticket, and put new work in the map, not in a log entry's "Next" line.

## Commands

- `scripts/ci.sh`: the one CI entrypoint (GitHub Actions runs exactly this). `--no-image` skips the image build.
- `uv run pytest`: unit tests (network blocked by pytest-socket) and integration tests (localhost only; needs `docker compose up -d --wait postgres-app silo`).
- `uv run atlas api | worker [--once] | migrate`: the three roles of the one image.
- `uv run atlas audit verify`: check the audit hash chain; exits 1 if it is broken.
- `uv run scripts/provision_archive.py --endpoint <url>`: the owner's one-off archive bucket/user provisioning (root credentials from `MINIO_ROOT_USER`/`MINIO_ROOT_PASSWORD`; see `docs/runbooks.md`).
- `uv run atlas companies seed`: create or update the companies in `configs/themes/ai-infrastructure.yaml` (the 12-company photonics universe, each with its layer and source path; idempotent).
- `uv run atlas companies resolve [--company <slug>]`: seed, then resolve each company to its CIK, LEI and listings through SEC's ticker file and submissions, GLEIF and OpenFIGI (keyless; needs `ATLAS_SEC_USER_AGENT`; live calls, so never in tests). Exact and corroborated identifiers commit (a listing gains its composite and share-class FIGIs and segment MIC); the rest, and every CIK↔LEI link, wait for the owner: `GET /api/v1/identity-mappings?review_state=pending`, `POST /api/v1/identity-mappings/{id}/confirm|reject` (audited). `atlas.identity.service.resolve_mention` resolves a mention (name, ticker + MIC, CIK, LEI, ISIN) against the universe first (rules in `docs/decisions.md`, "Entity resolution").
- `uv run atlas ingest --company <slug> [--key K]`: enqueue an ingest job; `atlas worker --once` runs it. It dispatches on the company's source path: `sec` (recorded fixtures exist for `lumentum` and `coherent`), or `exchange:hkex` (Innolight via HKEXnews: every request passes the fetch gate (the site register `configs/sources/sites.yaml`, the terms, robots.txt); HKEX's Terms of Use forbid automation, so without an IIS licence or written consent recorded it records a `blocked` gate decision and fetches nothing; `ATLAS_EXCHANGE_FIXTURES_DIR=tests/fixtures/hkexnews` replays hand-written fixtures, `ATLAS_EXCHANGE_LIVE=true` with `ATLAS_EXCHANGE_USER_AGENT` goes live; `GET /api/v1/companies/{id}/fetch-gate-decisions?status=blocked` lists blocks), or `exchange:fca-nsm` (IQE via the FCA National Storage Mechanism, allowed by its terms, through the same gate at 0.5 requests/s; fixtures in `tests/fixtures/fca-nsm`; LSE RNS and IQE's Brighter IR iframe are blocked in the register), or `exchange:amf` (Soitec via the AMF info-financière open API, Licence Ouverte, credited in each version's `metadata.announcement.attribution`; the register's `api_client` lets the documented API and its file links through although robots.txt disallows them for crawlers; French-only documents are archived, not retained; fixtures in `tests/fixtures/amf` (`scripts/make_amf_fixtures.py`); Euronext and soitec.com are blocked in the register). Fixture mode needs `ATLAS_SEC_FIXTURES_DIR=tests/fixtures/edgar`; `ATLAS_SEC_LIVE=true` fetches from SEC. With `ATLAS_HINDSIGHT_URL` set (and the template applied), each new parsed Source Version is then retained; `GET /api/v1/source-versions/{id}/memory` shows its sections. Each retain item (research, replay and evaluation banks alike) sends explicit `observation_scopes`, one per theme tag and no company scope, so observations consolidate across a theme's companies and documents; a company-scoped recall therefore returns facts and no observation (`docs/decisions.md`, "Observation scopes: one per theme"). `atlas jobs enqueue retain --key K --payload '{"source_version_id": "..."}'` retains one by hand. Add `--backfill` (to `ingest` or `jobs enqueue`) to make it backfill class: it and its retains run only in `ATLAS_BACKFILL_WINDOW` if one is set (comma-separated ranges; default empty: any time) and never use the budgets' interactive reserve. LLM-backed kinds are held by their provider's rolling 5 h budget (`codex`: Hindsight operations submitted, `ATLAS_CODEX_BUDGET_OPERATIONS`; `minimax`: role-call tokens, `ATLAS_MINIMAX_BUDGET_TOKENS`; `docs/runbooks.md`, "Universe rollout and quota budgets"). `ATLAS_RETAIN_EXTRACTOR=minimax` (unset by default) makes every retain item ask the shared Hindsight for its MiniMax extractor (`extractor: minimax` in the item's metadata; Hindsight's metadata routing; replay banks and evaluation banks send it too); `retain`, `poll_operation` and `reprocess` then spend their own budget, `hindsight_minimax` (`ATLAS_RETAIN_BUDGET_OPERATIONS`, 200 operations per window), and `codex` keeps `reflect`, `refresh_mental_model` and `replay`; the extractor asked for is recorded per section and operation (`extractor` in the memory read; null: the primary). Rules in `docs/decisions.md`, "Atlas's retains on MiniMax by metadata routing"; switching it on and back in `docs/runbooks.md`, "Retains on MiniMax". A company's first backfill ingest records an ingest plan (`GET /api/v1/ingest-plans`); `--max-retains N` retains at most N not-yet-retained versions, newest first (a rerun takes the next N). A 429 or outage pauses the Hindsight job kinds with backoff (≤ 1 h); `GET /api/v1/queue` shows the pause, the window and pending jobs by kind.
- `GET /api/v1/companies/{id}/financials?as_of=&metric=` (canonical metrics from `configs/financials/metrics.yaml`, derived quarters included), `GET /api/v1/companies/{id}/financial-observations?as_of=` and `GET /api/v1/financial-observations/{id}` (with its restatement history): as-of XBRL financials. Each ingest normalizes the company's latest companyfacts Source Version once, whether or not that run fetched it; `uv run atlas financials normalize [--company <slug>]` does so without an ingest (the backfill for versions recorded before normalization; `docs/runbooks.md`, "XBRL normalization backfill"); every fact takes its filing's `available_at` (rules in `docs/decisions.md`, "XBRL normalization"). A failed normalization doesn't fail the ingest: it is recorded in `financial_normalization_failure` (audited; the job's `financial_normalization` artifact has `status: failed`; `atlas_financial_normalizations_total{outcome}`) and retried by the next ingest.
- What a retained section says (memory-quality ticket 04; `docs/decisions.md`, "What a retained section says"): each retain item (production, replay and evaluation banks alike) carries a context built by `atlas.retention.context.section_context` (whose document, what kind and form, the period, the day it became public, the section, and who speaks: the filer; on a call transcript management and analysts, an analyst's question not the company's statement; on a manual import the publisher), `entities` (the filer's canonical name and every universe company or counterparty the section's text names, by passage selection's matcher, as written, `resolve_entities: false`) and display metadata after the provenance keys (`company_name`, `form`, `period`). Each memory document records the `retain_profile` (`retain-v2`; `retain-v1` before migration 0062), `retain_context` and `retain_entities` it was submitted with; `GET /api/v1/source-versions/{id}/memory` shows them and `current_retain_profile`. Stored sections reach a new profile only by the backfill (ticket 12).
- `uv run atlas sources import --company <slug> --file <path> --origin-url <URL> --published-at <ISO time with offset> [--title T]`: record a document the owner downloaded by hand (e.g. from HKEXnews, which Atlas may not fetch) as a `manual_import` Source Version, `available_at` = the given publication time (`publisher_timestamp`); parsed, put in its Evidence Family, retained if English, audited; the same bytes again change nothing.
- Retention triage (`ATLAS_RETENTION_TRIAGE=auto|on|off`; `auto`, the default, is on when LiteLLM is configured): a new version's `retain` first runs a `triage` job (`minimax`, pausable). It inherits the decisions of unchanged sections (content hash) from the predecessor version, skips boilerplate Item headings by rule, and asks the Triage role (rubric `backend/atlas/roles/prompts/triage.v3.md`, in up to `ATLAS_TRIAGE_WINDOWS_PER_SECTION` (10) windows per section) about the rest; exhibit indexes go to the role, not the rules (`triage-rules-v2`). Only `retain` sections go to Hindsight; skipped ones stay archived and citable. `GET /api/v1/triage?source_version_id=&company_id=&decision=&category=&method=&effective=` lists decisions (insert-only, audited). `POST /api/v1/source-versions/{id}/sections/{anchor}/retain` (`{reason, investigation_id?}`) retains a section on demand. A failed triage retains nothing: it is held or retried, and a job failed after its attempts is re-enqueued by `uv run atlas triage retry --source-version <id> | --failed` (gauge `atlas_triage_failed_jobs`). Windows overlap by `ATLAS_TRIAGE_WINDOW_OVERLAP_CHARS` (200). Rules in `docs/decisions.md`, "Retention triage".
- `uv run atlas triage audit [--sample N] [--company slug] [--seed S] [--backfill] [--wait]`: measure triage's misses (ticket 33). It draws a seeded sample of sections whose effective decision is `skip`, stratified by form and length band, and enqueues a `triage_audit` job (`minimax`, pausable, a few samples per attempt). The job gives each sample's archived parsed text, whole, to the full-section judge (role `triage_judge`, prompt `triage_judge.v2`: rubric v3's criteria; overlapping chunks only past `ATLAS_TRIAGE_JUDGE_MAX_CHARS`, 60,000, retained if any chunk is) and stores one insert-only `triage_audit` row per sample. `GET /api/v1/triage/audits[/{id}]` reads the audits with the summary: the miss rate with a Wilson 95% interval, by length band, category, method and form, and example misses with the anchor and the judge's reason. `--wait` prints the summary once the worker is done. See `docs/runbooks.md`, "Triage audit".
- `uv run atlas retention retry-failed [--since D | --all-history] [--error-class C]... [--company <slug>] [--interactive]`: re-enqueue (backfill class by default; audited) the sections not in memory. A section's outcome comes from its own Hindsight document whatever its operation's end (memory-quality ticket 03): stored with facts is `completed`, with none `zero_fact` after one reprocess, absent `cancelled` when the owner cancelled the operation (a state of its own, not a failure; migration `0068` moved the recorded cancellations there) or `failed` with a class (`permanent`, `transient`: a timeout or relayed 5xx, resubmitted with the queue's backoff up to `ATLAS_RETAIN_TRANSIENT_RETRIES` times, or `missing`). A section of an operation reporting `extraction_errors_count` is retried once and is `partial` if the errors persist. `atlas_retained_sections_total{outcome}`, `atlas_sections_not_in_memory{state,error_class}`, `atlas_partial_sections`; rules in `docs/decisions.md`, "A section's outcome comes from its own document"; `docs/runbooks.md`, "Retrying sections by class".
- `uv run atlas ledger correct-availability`: record (append-only, audited) the EDGAR dissemination-time correction for Source Versions ingested before that rule; idempotent (`docs/runbooks.md`).
- `uv run atlas ledger assign-families`: put parsed Source Versions recorded before Evidence Families into their family (new versions get one at ingest); idempotent. `GET /api/v1/source-versions/{id}` shows a version's `evidence_family`, `GET /api/v1/evidence-families/{id}` a family's members.
- `uv run atlas ledger reparse [--company <slug>] [--parser-version text-v3] [--key K]`: enqueue a `reparse` job (not pausable; no LLM): Source Versions recorded under an earlier parser (`text-v2`, `html-text-v1`) get a separate, insert-only `source_parse` record under the current parser from their archived raw bytes (audited `source_parse.created`; idempotent); the recorded parse never changes. `GET /api/v1/source-versions/{id}` lists `parses` and `current_parser_version`; `.../content?kind=parsed&parser_version=` serves one. The Investigator's extraction reads the current parse; an Assertion records its `parser_version` and is checked against that parse only; memory, triage, the Skeptic and provenance stay on the recorded parse (`docs/decisions.md`, "Re-parsing recorded Source Versions"; `docs/runbooks.md`).
- `POST /api/v1/memory/recall` (synchronous) and `POST /api/v1/memory/reflect` (a `reflect` job; `GET /api/v1/memory/reflect/{id}` for the answer): scoped by `company_ids` and `theme_ids`, every citation resolved to a Source Version section and labeled resolved, unverified or broken (rules in `docs/decisions.md`). Recall also takes `max_tokens`, `types`, `prefer_observations`, `query_timestamp` and `include_source_facts` (optional; memory-quality ticket 07) and returns each memory's `scores`, `entities` (name and ID) and `chunk_id`; with source facts an observation resolves from the answer, asking Hindsight only for a source the answer left out. Pointer recalls (the Scout's and the Skeptic's) send `ATLAS_POINTER_RECALL_MAX_TOKENS` (8192), budget high, `prefer_observations`, the investigation's as-of time as `query_timestamp` and the source facts, and each reading pointer stores its `score` and `entity_names` (migration `0063`); a replay's recalls send its cutoff (`docs/decisions.md`, "Recall as a reading index").
- `GET /api/v1/memory/health[?company_id=]` (memory-quality ticket 02; `atlas.retention.health`): what the research bank holds and lost, from Atlas's records (sections by retain state per company and for the bank, `partial` ones whose operation reported extraction errors, failed sections grouped by normalized error, pending by age) and Hindsight's read-only listings (observation scopes; each universe company's matching entities, `one_entity`); a failed listing is `unavailable` and the rest still answers. `uv run python scripts/memory_probe.py [--base-url] [--out]` runs the fixed probe recalls of `configs/memory/probes.yaml` (the five pilot questions, four Scout-style queries each; validated at load by `atlas.research.probes`) through `POST /api/v1/memory/recall` and reports memories, resolved citations, sections, companies, observation share, repeats and pointer-weight ranking to `.scratch/live-runs/<stamp>-memory-probe/`. See `docs/runbooks.md`, "Memory health".
- `atlas jobs enqueue extract_claims --key K --payload '{"source_version_ids": ["..."], "question": "..."}'`: the Investigator reads passages of those Source Versions and proposes Claims. The passages are chosen by `atlas.claims.selection` (memory-directed reading ticket 05; `docs/decisions.md`, "Passage selection: pointers and search, alternately"): the windows a term search (BM25) ranks highest for the optional question and the windows naming another known company, best first, with a floor of one passage for each periodic report, results release and results-call transcript (provider `tradingview`, type "Call transcript") and a ceiling per document (`ATLAS_INVESTIGATOR_MAX_PASSAGE_SHARE_PER_DOCUMENT`, a third of the passage budget; unused share passes on); a document with neither kind of window offers its lead windows. The job makes no recall. Each passage records every selection that chose it (`selected_by`: `search`, `entity:<id>`, `lead`; inside an investigation also `pointer:<query_index>`), and each Claim's read says which chose its passage (`passage_selected_by`). Then each quote is placed at the model's offsets or its one exact occurrence in the passage, if need be through a one-to-one fold of typographic hyphens, quotation marks and spaces (`offset_source` `model`/`located`/`folded`; several is `quote_ambiguous`; the stored quote is the archived text at the span), span-checked ones become Assertions, the rest are rejected with a reason. The Investigator's prompt is `investigator.v8`. A quote names both parties, or leaves the filer unnamed in an impersonal sentence of its own document that names the other party or the product and no other company (`party_basis` `filer`, else `named`); `capacity_constrained` needs language of constraint, and `owns` runs from the holder to the issuer (`wrong_direction`). A `capacity_constrained` Claim may be **company-level** (memory-directed reading ticket 09; `Claim.company_level`): proposed with no object text, or with one that names no product ("our products", "manufacturing capacity"), it is accepted with no object and no layer when the subject is the filer of the document (`company_level_not_filer`), the quote carries a constraint cue and it names no other company (`other_company_in_quote`); the other three bottleneck predicates keep the named-object rule (rules in `docs/decisions.md`, "A company-level constraint needs no named product"). A Claim's layer is optional and kept only when a taxonomy term of that layer (`atlas.claims.LAYER_TERMS`) occurs in the object text or the quote; a word several layers share ("InP", "indium phosphide") supports none, and the accepted Claim then has no layer (`layer_reason` `layer_unsupported`; `layer_term` is the supporting word otherwise). Rules in `docs/decisions.md`, "Claim checks" and "A layer only when the quote supports one". `GET /api/v1/claims` lists outcomes; `GET /api/v1/claim-extractions/{id}` (the job's artifacts name it) shows passages and progress. Needs LiteLLM and Hindsight; pausable.
- Counterparty companies (pilot-fixes ticket 05; `docs/decisions.md`, "Counterparty companies"): a Claim may name a company object outside the universe (`object_name`, the name as the quote writes it). With `ATLAS_SEC_USER_AGENT` set, extraction resolves it (SEC ticker file and submissions, GLEIF; exact normalized name, exactly one entity) and an accepted Claim creates a `counterparty` company (`Company.role`; audited), so the edge has both ends; otherwise the Claim is rejected `unresolved_company` or `ambiguous_company`. A counterparty is never ingested (`atlas ingest` refuses it) and never an investigation seed; it shows on the edge table, the theme map (`counterparties`) and its dossier; `GET /api/v1/companies?role=researched|counterparty` filters. The owner promotes it by adding it to the theme config or committing its Candidate.
- `atlas jobs enqueue review_relationships --key K --payload '{}'` (or `{"assertion_ids": [...]}`): machine-review Assertions into Relationships (typed, directed edges, identified by subject, predicate and object; layer-tagged only when their Evidence names a layer). Deterministic checks (verbatim span, Tier A, unhedged directional language) plus the Reviewer role's answers (`reviewer.v5`: direction, hedge and layer, each on its own; no layer answer is needed for an edge with none) make an edge `machine_reviewed`; anything else goes to the exceptions queue (`needs_human_review`); co-mention forms no edge. Evidence that brings another layer than its edge has joins it with `layer_conflict` (the edge goes to the queue) instead of making a second edge; an edge with no layer takes the first layer later Evidence brings. A company's own `capacity_constrained` statement that names no product forms its **company-level edge** (`Relationship.company_level`: no object company, no object text, no layer; the reserved empty `object_key`, so one per company, and every further such Assertion adds Evidence to it); a risk factor's "could" is a Claim but never machine-reviewed (`hedged_language`). It is in the edge table, on the company's dossier and on the theme map under its company. `GET /api/v1/relationships?layer=&review_state=&predicate=&company_id=&sort=&order=` is the edge table (Evidence and family counts; `layer=none` is the edges with no layer), `GET /api/v1/relationships/exceptions` the queue, `GET /api/v1/relationships/layer-duplicates` the read-only report of edges recorded before migration 0055 that differ only by layer (left as they are), `GET /api/v1/relationships/{id}` an edge with its Evidence spans, `POST /api/v1/relationships/{id}/review` the owner's approve/reject (audited). Needs LiteLLM and Hindsight; pausable.
- `GET /api/v1/themes` and `GET /api/v1/themes/{id}/map` (the Theme explorer: each theme's companies by layer with coverage gaps, the Relationships between them (those with no layer under their companies, not under a layer), its Candidates, and the Bottlenecks mental model's open gaps with a `status` when absent) and `GET /api/v1/companies/{id}/dossier?as_of=` (the Company dossier: identity and listings, pending identity reviews, themes, Source Documents, Relationships out and in, as-of financials, fetch-gate blocks). Pages `frontend/app/themes/`, `app/theme/` and `app/company/`.
- `uv run atlas hindsight apply-template`: dry-run, then import `configs/hindsight/bank-template.json` into the research bank, recording its version. A mental model whose trigger could run away (no explicit `refresh_after_consolidation: false`, no `refresh_cron`, no minimum interval) makes the template invalid.
- The bank template's missions and layer label (memory-quality ticket 05; `docs/decisions.md`, "The bank template's missions and the layer label"): `retain_mission` has an ignore list (safe-harbor, certifications, exhibit lists, signature blocks, generic risk language) and attributes each statement to who made it; `observations_mission` stands alone (it replaces Hindsight's built-in rules); `entity_labels` has one group, `layer`, whose values are the Claim layer taxonomy's (`atlas.claims.LAYERS`; a unit test fails when they differ), `tag: true`, so a recall can be scoped by `layer:<value>`. The fake's `script_fact_labels` gives a derived fact its labels. `uv run python spikes/hindsight/mission_compare_05.py [--show]` compares the old and new missions with `dry-run-extract` on the local spike Hindsight (≤ 12 LLM requests; live, so the lead's to run).
- `GET /api/v1/mental-models[/{id}]`: the template's mental models (Theme status, Bottlenecks) with content, history, citations resolved like a reflect answer's, and Atlas's refresh records. `atlas worker` enqueues each model's daily `refresh_mental_model` job from `ATLAS_MENTAL_MODEL_REFRESH_AT` (06:30 UTC); the job is pausable and skips a model refreshed inside its minimum interval or with nothing new. `atlas jobs enqueue refresh_mental_model --key K --payload '{"mental_model_id": "theme-status"}'` asks for one by hand.
- `uv run atlas jobs enqueue discover --key K --payload '{"theme": "photonics", "question": "..."}'`: a discovery. The Scout (a LiteLLM role call; the Bottlenecks mental model's content as its open gaps) writes at most `ATLAS_DISCOVERY_MAX_QUERIES` (≤ 10) queries, SearXNG (`ATLAS_SEARXNG_URL`, engines `ATLAS_SEARXNG_ENGINES`, default `bing,brave`; language `ATLAS_SEARXNG_LANGUAGE`, default `en`, on every search) searches them, and the results become Tier C leads deduplicated by canonical URL, never Evidence. `GET /api/v1/leads[?theme=]` and `GET /api/v1/discoveries[/{id}]` (queries, unresponsive engines, errors) read them. EDGAR full-text search is the second channel (pilot fix 12; `ATLAS_DISCOVERY_EDGAR_FTS`, `auto`: on with `ATLAS_SEC_USER_AGENT`; `ATLAS_DISCOVERY_EDGAR_MAX_HITS`, 10; `docs/decisions.md`, "EDGAR full-text search as a discovery channel"): a query's `filing_phrase` (Scout `scout.v4`, Skeptic `skeptic-plan.v4`) is searched in 10-K/10-Q/8-K/20-F/6-K/40-F filings of the 18 months before the as-of time, and each hit becomes an `edgar_fts` lead (filer, CIK, form, date; `filing.ingestable` for a universe company's filing not yet archived); `propose_candidates` proposes a filer outside the universe by its CIK, without the mention extractor, and an investigation's Scout enqueues it (`filers_only`). Only a specific phrase is searched (memory-directed reading, ticket 04; `docs/decisions.md`, "Specific filing phrases; a filer needs a kept hit"): at least two words, or a product or layer term of the lead-ranking config (`terms`); any other is recorded as a `skipped` search with its `skip_reason` (each query's `edgar` in `GET /api/v1/discoveries/{id}`; `filing_searches_skipped` in the job's artifacts). A filer becomes a Candidate only when one of its filing leads is kept by lead ranking (scored against its query and purpose; a hit of a bare vocabulary term such as `VCSEL` or `CW laser` is demoted); the others are listed in the `propose_candidates` job's `filers_below_threshold` and their leads stay unexamined. The client is `atlas.discovery.edgar_fts`; tests use `tests/fakes/edgar_fts.py` over `tests/fixtures/edgar-fts/`.
- Candidates (§8.3): with `ATLAS_SEC_USER_AGENT` set, each `discover` job enqueues `propose_candidates` (pausable; `atlas jobs enqueue propose_candidates --key K --payload '{"discovery_id": "..."}'` by hand). The mention extractor role reads the discovery's leads not examined before (title + snippet, 10 per call) and lists the companies they name (name, ticker?, exchange?); each goes through `resolve_mention`, and an unseeded match becomes a Candidate in the discovery's theme (keyed by CIK, else LEI, else normalized name; never committed automatically). `GET /api/v1/candidates[/{id}]?state=&theme=` reads them with their resolution and leads (and `counterparty_company_id`: the counterparty company a commit would promote). The owner's `POST /api/v1/candidates/{id}/commit` (`{slug?, display_name?, country?, layer?, cik?, note?}`) adds the company to the universe stored in the database (`universe_company`, read by `atlas.companies.extend_universe`: ingest, `atlas ingest` and retention tags see it) and enqueues its SEC ingest when a CIK was resolved, else records that no automated source exists yet; `POST .../reject` (`{reason}`) keeps it `rejected`. Both audited; Candidates are never deleted. Metric `atlas_candidates{state}`.
- `POST /api/v1/investigations` (`{"theme": "photonics", "question": "...", "seed_company_ids"?, "as_of"?, "budgets"?}`): an investigation. It runs a plan of `investigation_task` jobs (pausable) in one run, which grows once after the Scout (multi-hop Investigators, below): Scout (a discovery; its top-ranked leads are kept, each with its score and reasons: `atlas.discovery.ranking`, config `configs/discovery/lead-ranking.yaml` (`ATLAS_LEAD_RANKING_CONFIG`): query and purpose topic terms (company names and years excluded; none, not kept), universe company names, product and layer terms, denied and demoted hosts (profile and social sites among them), the universe companies' own sites, generic titles ("About us") and non-English results demoted; version 3: an EDGAR filing hit is scored the same way, a hit of a bare vocabulary term demoted) → one Investigator per seed company, and per other researched company the Scout's reading pointers name while the company budget has room (an extraction of the Source Versions its pointers name, best pointer first, then its latest parsed ones as of `as_of`) → Skeptic (it asks Memory each bear-checklist item for each company the accepted Claims name, across the theme (at most 6 companies × 6 items, no LLM call), and those answers are its own reading pointers (`query_kind` `bear_checklist`, with the `checklist_item` and the company asked about; the Investigators read by the Scout's only); it reads the archived Tier A Source Versions they lead to, a company Memory points at nothing of through its latest 10-K and 10-Q (the fallback, `skeptic_documents_fallback`), its passages chosen like the Investigator's (pointer and search windows alternately, the search's terms the bear-checklist queries'); its plan call writes only its own SearXNG and EDGAR queries (`skeptic-plan.v5`), so an empty or quarantined plan still leaves it reading; no Memory is sent to it: Memory chooses what it reads (`docs/decisions.md`, "The Skeptic reads where Memory points"); each accepted item is a `counterevidence` Assertion of one kind, never both: a contradiction of a named Claim (it says how: denies, limits, dates; its quote must name the Claim's subject or object, else code stores it as bear context with the reason) or bear context about a company, attached to no Claim (a table row with no words only with its figure's name and period); only a contradiction is independent (an Evidence Family none of the supporting Claims use), marks a finding contradicted or may disprove a company premise; Memory and other roles' output are never witnesses; `docs/decisions.md`, "Contradiction or bear context") ∥ Financial Analyst (proposes scenario inputs from the accepted Claims and the seed companies' as-of XBRL figures, each sourced or estimated; skipped without an accepted Claim) → Editor (a draft research card from the accepted Claims, with the contradictions (`contradictions`), the bear context by checklist item and company (`bear_context`), what was searched and read (`searched`, `read`, a row per Investigator) and the pointed companies no Investigator read (`not_read`); with no accepted Claim the card has no finding, only that and the open questions for the next round; the Editor cites each Claim by a short reference, `c1`, `c2`, … (`editor.v6`), which code maps back; an answer cut off at the Editor's output cap is asked once more with the cap doubled, up to `ATLAS_EDITOR_MAX_OUTPUT_TOKENS` (16,384), and if it still fails, or is quarantined, the card is code's: no finding, `editor_failure` and `claims_by_company`, and the investigation stops `needs_review`; any role's answer cut off at its cap is a `truncated` role call, with no repair, handled as a quarantine: `docs/decisions.md`, "A cut-off answer is not a schema failure; the card never goes missing"). Budgets: ≤ 2 rounds, `ATLAS_INVESTIGATION_MAX_LEADS` (10) leads, `ATLAS_INVESTIGATION_MAX_DOCUMENTS` (25) documents (split fairly across the Investigators), `ATLAS_INVESTIGATION_MAX_COMPANIES` (6) Investigators a round, the seeds counted (`budgets.max_companies` may lower it), `ATLAS_INVESTIGATION_MAX_PASSAGES` (24) passages per Investigator, chosen across its documents (`atlas.claims.selection`) by two channels taken alternately, so neither crowds the other out: the windows the round's reading pointers lead to (for each pointer, the window of the pointed section that best matches its Memory text; by recall rank), and the windows a term search ranks highest for the round's question and the Scout's queries with the entity-tagged ones (by BM25 score; the only way to a document not yet retained, such as a new transcript); lead windows come last. Each periodic report, results release and results-call transcript (provider `tradingview`, type "Call transcript") with a candidate keeps one passage, and one document takes at most `ATLAS_INVESTIGATOR_MAX_PASSAGE_SHARE_PER_DOCUMENT` (a third) of the budget while others have candidates. The Investigator makes no recall of its own, and no Memory text is sent to it. The card's `read` gives each document's passages and how they were selected (`selections`: pointer, search, entity, lead), and the Evidence tray each Claim's `passage_selected_by`, `ATLAS_RUN_TOKEN_BUDGET` tokens. It stops `answered`, `no_new_independent_evidence`, `budget_exhausted` (resumable: `POST .../resume {"token_budget"}`), `needs_review` or `premise_disproven` (`POST .../premises/{key}/disprove`); an LLM outage pauses it. `GET /api/v1/investigations[/{id}[/events]]` reads them (with the Evidence tray, `evidence`, the reading pointers, `pointers`, and the companies they name, `pointed_companies`). `POST .../follow-up {"question"}` launches the one follow-up round on an open question of the research card (same plan as round 2, same run and budgets; only Source Versions not yet read; recorded in `investigation_follow_up`; rules in `docs/decisions.md`). The research workbench pages: `frontend/app/workbench/` (start one, list them) and `app/investigation/` (plan, reading pointers, events, Evidence tray, counterevidence, open questions, budget use; resume, disprove, follow-up, save as Hypothesis; polls while running).
- Reading pointers (memory-directed reading ticket 01; `docs/decisions.md`, "Memory as the reading index"; spec `.scratch/atlas-memory-directed-reading/spec.md`): once an investigation's Scout has its queries, its task asks Memory the round's question and each query across the theme (one theme-scoped recall each; no LLM call, no budget) and stores every Source Version section a resolved memory leads to as an insert-only `reading_pointer` row (query index and text, the recall's rank, the memory's ID, type and text, the section and its offsets, the company; none for a version available after `as_of`), audited once per task (`investigation.pointers_recorded`, actor `atlas-scout`). `GET /api/v1/investigations/{id}` returns them as `pointers`, and a Research Snapshot carries them (`memory.reading_pointers`); the Scout task's artifacts count `pointer_recalls`, `pointer_recalls_failed`, `memories_recalled`, `pointers` and `pointers_by_company`. A failed recall is a `pointer_recall_failed` event and the Scout goes on with fewer pointers; a Hindsight quota or outage pauses the task. Memory stays an index: a pointer's text is never quoted, never a witness and never sent to a role. The pointers choose the Investigators' passages (ticket 05, above) and the companies and documents read (ticket 06, below); the Skeptic's reading by them is ticket 07. Code: `atlas.investigations.pointers`.
- Multi-hop Investigators (memory-directed reading ticket 06; `docs/decisions.md`, "Multi-hop Investigators: the plan grows after the Scout"): the seeds are where the reading starts, not where it ends. When a round's Scout has succeeded, the companies its pointers name are ranked by weight (the sum over a company's pointers of 1 / the pointer's rank in its recall) and the plan gains an `investigator:<slug>` task, with its own `company:<slug>` premise, for each researched company that is not a seed, in rank order, while the company budget has room (`ATLAS_INVESTIGATION_MAX_COMPANIES`, 6 Investigators a round, the seeds counted; `budgets.max_companies` in the request, 1–25; migration `0058`, `investigation.max_companies`). Seeds always have theirs; a counterparty never gets one; the Skeptic, the Financial Analyst and the Editor wait for the added Investigators too, and the Financial Analyst still works for the seed companies only. An Investigator reads the Source Versions its company's pointers name first (best pointer first), then its latest ones, within its share of the document budget (`documents_pointed` in its artifacts). Read side: `GET /api/v1/investigations/{id}` gives `pointed_companies` (per round: `pointers`, `score`, `best_rank`, `outcome` `seed`/`added`/`no_room`/`premise_disproven`, `task_key`), `budgets.max_companies` and `usage.companies`; an added task's artifacts hold `added_for_pointers`; the Scout's hold the ranking (`pointed_companies`, `investigators_added`, `companies_not_read`); a `companies_ranked` event records it; the research card lists the pointed companies no Investigator read (`not_read`, with the reason), so the next investigation can seed them. A follow-up round grows the same way from its own question's pointers. Code: `atlas.investigations.companies` (the ranking and the allotment, pure) and `Investigations._grow` in `atlas.investigations.service`.
- TradingView (ticket 31; an owner override of TradingView's display-only terms, **off by default**: `ATLAS_TRADINGVIEW_ENABLED`; `docs/decisions.md`, "Owner override: TradingView as a source"; `docs/runbooks.md`, "TradingView (owner override)"): in the cluster Atlas reaches it through the owner's read-only MCP proxy with configuration alone (`docs/runbooks.md`, "In the cluster: the MCP proxy"); outside it, `uv run atlas tradingview login` gets Atlas its own OAuth token (MCP authorization spec: resource metadata, dynamic registration, code + PKCE, loopback redirect) into the gitignored token file (mode 0600; refreshed automatically); `atlas tradingview check --symbol NASDAQ:LITE` makes one catalog call and prints counts only. `atlas jobs enqueue tradingview_catalog --key K --payload '{"company": "lumentum"}'` stores the company's `tradingview_symbol` documents as catalog metadata (`GET /api/v1/tradingview/catalog`) and its news headlines as Tier C leads (`origin: tradingview_news`), then enqueues `tradingview_transcripts`: transcript views become Tier B Source Versions (provider `tradingview`, `available_at` = the event's reported time), parsed by `tradingview-transcript-v1`. Three tools only, ≤ 1 request/s, ≤ `ATLAS_TRADINGVIEW_MAX_CALLS_PER_JOB` calls per job, counted in the `tradingview` budget; every stored item records the override. Fixtures (`tests/fixtures/tradingview/`) are synthetic.
- `POST /api/v1/hypotheses/{id}/scenarios` (`{"version", "as_of"?, "note"?, "assumptions"?}`), `GET /api/v1/hypotheses/{id}/scenarios[/{scenario_id}]?version=`: deterministic low/base/high scenarios on a Hypothesis version (§8.2 with BOM share: units × share × downstream price × BOM share → revenue × margin → contribution × multiple → EV − net debt → per share; revenue / reported revenue), ±20% single-input sensitivity, canonical JSON outputs hashed (byte-identical on recompute; each read recomputes and says so). Every input is `sourced` (an as-of XBRL observation, equal in every case and in the table's currency, or an available Assertion), `estimated` (with a basis) or `missing` (blocks its lines); anything else is refused (422). Without `assumptions`, the tables the investigation's Financial Analyst proposed (409 if none). The cutoff defaults to the investigation's `as_of`. Scenarios are insert-only and audited (rules in `docs/decisions.md`, "Scenarios").

A refusal is 422 `publish_gate_failed` with typed `failures` (`relationship_not_approved` names the edges). Metric `atlas_research_snapshots_total`; contents in `docs/decisions.md`, "The publish gate and Research Snapshots".

- `.scratch/`: the local issue tracker (the decision map and build tickets)

## Conventions

- Test-first at agreed seams only; test behavior through public interfaces, never internals. Real Postgres, never SQLite.
- Settings are `ATLAS_*` env vars (or `.env`), validated at startup. Optional providers log `<provider> disabled: missing <VAR>` once.
- Ruff and strict pyright must be clean; TypeScript is strict.
- Record each ticket's files, tests and results in `docs/implementation-log.md`. Never claim a live integration was tested when only fixtures were.

## Agent skills

### Issue tracker

### Triage labels

Default five-role vocabulary (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`). See `docs/agents/triage-labels.md`.

### Building, releasing and the pilot

- `docs/agents/implementer-brief.md`: what the lead hands each implementer agent (test-first at the seams, local checks only, commit and report; the lead pushes and runs the runners).
- `release-atlas` (skill): integrate ticket branches, chain migrations, release a tag and open the home-ops PR; the owner merges.
- `pilot-review` (skill): run a pilot investigation on production and review every accepted Claim against its span; results in `.scratch/pilot/results.md`, defects as tickets.

### Hindsight skills

- `hindsight-docs` is the Hindsight 0.10.1 documentation and OpenAPI schema, pinned to the server version. The feature matrix and recordings win where they disagree.
- `hindsight-self-hosted` gives development memory in the **`atlas-dev`** bank on the owner's shared Hindsight, via the `hindsight` CLI. Never use Atlas's research banks for it, and keep decisions in the repo.
