# Atlas Research: agent guide

Evidence-driven investment research platform built around Hindsight. Start with `START_HERE.md`; the authoritative spec is `hindsight_investment_research_build_plan.md` (v1.1).

**Current effort:** the pilot review. Orient at its map, `.scratch/atlas-pilot-review/map.md`, before choosing work: take the first open, unblocked ticket, and put new work in the map, not in a log entry's "Next" line.

**Roadmap planning:** when revisiting priorities or specifying the post-pilot effort, read [the 4 October roadmap proposal](docs/research/proposed-roadmap-2026-10-04.md), preserved at the owner's request. It proposes sequencing changes; the pilot map remains the execution authority until accepted changes are recorded there.

## Commands

- `scripts/ci.sh [static|suite] [--no-image]`: the one CI entrypoint (GitHub Actions runs exactly this): `static` (lint, types, frontend unit tests, API client; no Docker) runs on GitHub's runners, then `suite` (Compose services, pytest, e2e, image) on the self-hosted scale set; no argument runs both. `--no-image` skips the image build. Main requires the `ci` job (green only when both stages are); `docs/deployment.md`, "CI".
- `uv run pytest`: unit tests (network blocked by pytest-socket) and integration tests (localhost only; needs `docker compose up -d --wait postgres-app silo`).
- `uv run atlas api | worker [--once] | migrate`: the three roles of the one image.
- `uv run atlas audit verify`: check the audit hash chain; exits 1 if it is broken.
- `uv run scripts/provision_archive.py --endpoint <url>`: the owner's one-off archive bucket/user provisioning (root credentials from `MINIO_ROOT_USER`/`MINIO_ROOT_PASSWORD`; see `docs/runbooks.md`).
- `uv run atlas companies seed`: create or update the companies in `configs/themes/ai-infrastructure.yaml` (the 12-company photonics universe, each with its layer and source path; idempotent).
- `uv run atlas companies resolve [--company <slug>]`: seed, then resolve each company to its CIK, LEI and listings through SEC's ticker file and submissions, GLEIF and OpenFIGI (keyless; needs `ATLAS_SEC_USER_AGENT`; live calls, so never in tests). Exact and corroborated identifiers commit (a listing gains its composite and share-class FIGIs and segment MIC); the rest, and every CIK↔LEI link, wait for the owner: `GET /api/v1/identity-mappings?review_state=pending`, `POST /api/v1/identity-mappings/{id}/confirm|reject` (audited). `atlas.identity.service.resolve_mention` resolves a mention (name, ticker + MIC, CIK, LEI, ISIN) against the universe first (rules in `docs/decisions.md`, "Entity resolution").
- `uv run atlas ingest --company <slug> [--key K]`: enqueue an ingest job; `atlas worker --once` runs it. It dispatches on the company's source path: `sec` (recorded fixtures exist for `lumentum` and `coherent`), or `exchange:hkex` (Innolight via HKEXnews: every request passes the fetch gate (the site register `configs/sources/sites.yaml`, the terms, robots.txt); HKEX's Terms of Use forbid automation, so without an IIS licence or written consent recorded it records a `blocked` gate decision and fetches nothing; `ATLAS_EXCHANGE_FIXTURES_DIR=tests/fixtures/hkexnews` replays hand-written fixtures, `ATLAS_EXCHANGE_LIVE=true` with `ATLAS_EXCHANGE_USER_AGENT` goes live; `GET /api/v1/companies/{id}/fetch-gate-decisions?status=blocked` lists blocks), or `exchange:fca-nsm` (IQE via the FCA National Storage Mechanism, allowed by its terms, through the same gate at 0.5 requests/s; fixtures in `tests/fixtures/fca-nsm`; LSE RNS and IQE's Brighter IR iframe are blocked in the register), or `exchange:amf` (Soitec via the AMF info-financière open API, Licence Ouverte, credited in each version's `metadata.announcement.attribution`; the register's `api_client` lets the documented API and its file links through although robots.txt disallows them for crawlers; French-only documents are archived, not retained; fixtures in `tests/fixtures/amf` (`scripts/make_amf_fixtures.py`); Euronext and soitec.com are blocked in the register). Fixture mode needs `ATLAS_SEC_FIXTURES_DIR=tests/fixtures/edgar`; `ATLAS_SEC_LIVE=true` fetches from SEC. With `ATLAS_HINDSIGHT_URL` set (and the template applied), each new parsed Source Version is then retained; `GET /api/v1/source-versions/{id}/memory` shows its sections. Each retain item (research, replay and evaluation banks alike) sends explicit `observation_scopes`, one per theme tag and no company scope, so observations consolidate across a theme's companies and documents; a company-scoped recall therefore returns facts and no observation (`docs/decisions.md`, "Observation scopes: one per theme"). `atlas jobs enqueue retain --key K --payload '{"source_version_id": "..."}'` retains one by hand. Add `--backfill` (to `ingest` or `jobs enqueue`) to make it backfill class: it and its retains run only in `ATLAS_BACKFILL_WINDOW` if one is set (comma-separated ranges; default empty: any time) and never use the budgets' interactive reserve. LLM-backed kinds are held by their provider's rolling 5 h budget (`codex`: Hindsight operations submitted, `ATLAS_CODEX_BUDGET_OPERATIONS`; `hindsight_consolidation`: the research bank's consolidation rounds, `ATLAS_CONSOLIDATE_BUDGET_ROUNDS`; `minimax`: role-call tokens, `ATLAS_MINIMAX_BUDGET_TOKENS`; `docs/runbooks.md`, "Universe rollout and quota budgets"). `ATLAS_RETAIN_EXTRACTOR=minimax` (unset by default) makes every retain item ask the shared Hindsight for its MiniMax extractor (`extractor: minimax` in the item's metadata; Hindsight's metadata routing; replay banks and evaluation banks send it too); `retain`, `poll_operation` and `reprocess` then spend their own budget, `hindsight_minimax` (`ATLAS_RETAIN_BUDGET_OPERATIONS`, 200 operations per window), and `codex` keeps `reflect`, `refresh_mental_model` and `replay`; the extractor asked for is recorded per section and operation (`extractor` in the memory read; null: the primary). Rules in `docs/decisions.md`, "Atlas's retains on MiniMax by metadata routing"; switching it on and back in `docs/runbooks.md`, "Retains on MiniMax". A company's first backfill ingest records an ingest plan (`GET /api/v1/ingest-plans`); `--max-retains N` retains at most N not-yet-retained versions, newest first (a rerun takes the next N). A 429 or outage pauses the Hindsight job kinds with backoff (≤ 1 h); `GET /api/v1/queue` shows the pause, the window and pending jobs by kind.
- `GET /api/v1/companies/{id}/financials?as_of=&metric=` (canonical metrics from `configs/financials/metrics.yaml`, derived quarters included), `GET /api/v1/companies/{id}/financial-observations?as_of=` and `GET /api/v1/financial-observations/{id}` (with its restatement history): as-of XBRL financials. Each ingest normalizes the company's latest companyfacts Source Version once, whether or not that run fetched it; `uv run atlas financials normalize [--company <slug>]` does so without an ingest (the backfill for versions recorded before normalization; `docs/runbooks.md`, "XBRL normalization backfill"); every fact takes its filing's `available_at` (rules in `docs/decisions.md`, "XBRL normalization"). A failed normalization doesn't fail the ingest: it is recorded in `financial_normalization_failure` (audited; the job's `financial_normalization` artifact has `status: failed`; `atlas_financial_normalizations_total{outcome}`) and retried by the next ingest.
- What a retained section says (memory-quality ticket 04; `docs/decisions.md`, "What a retained section says"): each retain item (production, replay and evaluation banks alike) carries a context built by `atlas.retention.context.section_context` (whose document, what kind and form, the period, the day it became public, the section, and who speaks: the filer; on a call transcript management and analysts, an analyst's question not the company's statement; on a manual import the publisher), `entities` (the filer's canonical name and every universe company or counterparty the section's text names, by passage selection's matcher, as written, `resolve_entities: false`) and display metadata after the provenance keys (`company_name`, `form`, `period`). Each memory document records the `retain_profile` (`retain-v2`; `retain-v1` before migration 0062), `retain_context` and `retain_entities` it was submitted with; `GET /api/v1/source-versions/{id}/memory` shows them and `current_retain_profile`. Stored sections reach a new profile only by the backfill (ticket 12).
- `uv run atlas sources import --company <slug> --file <path> --origin-url <URL> --published-at <ISO time with offset> [--title T]`: record a document the owner downloaded by hand (e.g. from HKEXnews, which Atlas may not fetch) as a `manual_import` Source Version, `available_at` = the given publication time (`publisher_timestamp`); parsed, put in its Evidence Family, retained if English, audited; the same bytes again change nothing.
- Retention triage (`ATLAS_RETENTION_TRIAGE=auto|on|off`; `auto`, the default, is on when LiteLLM is configured): a new version's `retain` first runs a `triage` job (`minimax`, pausable). It inherits the decisions of unchanged sections (content hash) from the predecessor version, skips boilerplate Item headings by rule, and asks the Triage role (rubric `backend/atlas/roles/prompts/triage.v3.md`, in up to `ATLAS_TRIAGE_WINDOWS_PER_SECTION` (10) windows per section) about the rest; exhibit indexes go to the role, not the rules (`triage-rules-v2`). Only `retain` sections go to Hindsight; skipped ones stay archived and citable. `GET /api/v1/triage?source_version_id=&company_id=&decision=&category=&method=&effective=` lists decisions (insert-only, audited). `POST /api/v1/source-versions/{id}/sections/{anchor}/retain` (`{reason, investigation_id?}`) retains a section on demand. A failed triage retains nothing: it is held or retried, and a job failed after its attempts is re-enqueued by `uv run atlas triage retry --source-version <id> | --failed` (gauge `atlas_triage_failed_jobs`). Windows overlap by `ATLAS_TRIAGE_WINDOW_OVERLAP_CHARS` (200). Rules in `docs/decisions.md`, "Retention triage".
- `uv run atlas triage audit [--sample N] [--company slug] [--seed S] [--backfill] [--wait]`: measure triage's misses (ticket 33). It draws a seeded sample of sections whose effective decision is `skip`, stratified by form and length band, and enqueues a `triage_audit` job (`minimax`, pausable, a few samples per attempt). The job gives each sample's archived parsed text, whole, to the full-section judge (role `triage_judge`, prompt `triage_judge.v2`: rubric v3's criteria; overlapping chunks only past `ATLAS_TRIAGE_JUDGE_MAX_CHARS`, 60,000, retained if any chunk is) and stores one insert-only `triage_audit` row per sample. `GET /api/v1/triage/audits[/{id}]` reads the audits with the summary: the miss rate with a Wilson 95% interval, by length band, category, method and form, and example misses with the anchor and the judge's reason. `--wait` prints the summary once the worker is done. See `docs/runbooks.md`, "Triage audit".
- `uv run atlas retention retry-failed [--since D | --all-history] [--error-class C]... [--company <slug>] [--interactive]`: re-enqueue (backfill class by default; audited) the sections not in memory. A section's outcome comes from its own Hindsight document whatever its operation's end (memory-quality ticket 03): stored with facts is `completed`, with none `zero_fact` after one reprocess, absent `cancelled` when the owner cancelled the operation (a state of its own, not a failure; migration `0068` moved the recorded cancellations there) or `failed` with a class (`permanent`, `transient`: a timeout or relayed 5xx, resubmitted with the queue's backoff up to `ATLAS_RETAIN_TRANSIENT_RETRIES` times, or `missing`). A section of an operation reporting `extraction_errors_count` is retried once and is `partial` if the errors persist. `atlas_retained_sections_total{outcome}`, `atlas_sections_not_in_memory{state,error_class}`, `atlas_partial_sections`; rules in `docs/decisions.md`, "A section's outcome comes from its own document"; `docs/runbooks.md`, "Retrying sections by class".
- `uv run atlas ledger correct-availability`: record (append-only, audited) the EDGAR dissemination-time correction for Source Versions ingested before that rule; idempotent (`docs/runbooks.md`).
- `uv run atlas ledger assign-families`: put parsed Source Versions recorded before Evidence Families into their family (new versions get one at ingest); idempotent. `GET /api/v1/source-versions/{id}` shows a version's `evidence_family`, `GET /api/v1/evidence-families/{id}` a family's members.
- `uv run atlas ledger reparse [--company <slug>] [--parser-version text-v3] [--key K]`: enqueue a `reparse` job (not pausable; no LLM): Source Versions recorded under an earlier parser (`text-v2`, `html-text-v1`) get a separate, insert-only `source_parse` record under the current parser from their archived raw bytes (audited `source_parse.created`; idempotent); the recorded parse never changes. `GET /api/v1/source-versions/{id}` lists `parses` and `current_parser_version`; `.../content?kind=parsed&parser_version=` serves one. The Investigator's extraction reads the current parse; an Assertion records its `parser_version` and is checked against that parse only; memory, triage, the Skeptic and provenance stay on the recorded parse (`docs/decisions.md`, "Re-parsing recorded Source Versions"; `docs/runbooks.md`).
- `POST /api/v1/memory/recall` (synchronous) and `POST /api/v1/memory/reflect` (a `reflect` job; `GET /api/v1/memory/reflect/{id}` for the answer): scoped by `company_ids` and `theme_ids`, every citation resolved to a Source Version section and labeled resolved, unverified or broken (rules in `docs/decisions.md`). Recall also takes `max_tokens`, `types`, `prefer_observations`, `query_timestamp` and `include_source_facts` (optional; memory-quality ticket 07) and returns each memory's `scores`, `entities` (name and ID) and `chunk_id`; with source facts an observation resolves from the answer, asking Hindsight only for a source the answer left out. Pointer recalls (the Scout's and the Skeptic's) send `ATLAS_POINTER_RECALL_MAX_TOKENS` (8192), budget high, `prefer_observations`, the investigation's as-of time as `query_timestamp` and the source facts, and each reading pointer stores its `score` and `entity_names` (migration `0063`); a replay's recalls send its cutoff (`docs/decisions.md`, "Recall as a reading index"). A reflect takes `budget` (default `mid`) and `exclude_mental_models` (default true); a mental model an answer read is a citation of kind `mental_model`, never resolved to a section. Each reflect and each mental-model refresh Atlas submits is one unit of the `codex` budget (memory-quality ticket 10).
- `GET /api/v1/memory/health[?company_id=]` (memory-quality ticket 02; `atlas.retention.health`): what the research bank holds and lost, from Atlas's records (sections by retain state per company and for the bank, `partial` ones whose operation reported extraction errors, failed sections grouped by normalized error, pending by age) and Hindsight's read-only listings (observation scopes; each universe company's matching entities, `one_entity`); a failed listing is `unavailable` and the rest still answers. `uv run python scripts/memory_probe.py [--base-url] [--out]` runs the fixed probe recalls of `configs/memory/probes.yaml` (the five pilot questions, four Scout-style queries each; validated at load by `atlas.research.probes`) through `POST /api/v1/memory/recall` and reports memories, resolved citations, sections, companies, observation share, repeats and pointer-weight ranking to `.scratch/live-runs/<stamp>-memory-probe/`. See `docs/runbooks.md`, "Memory health". `versions` (pilot-review ticket 22; `atlas.retention.coverage`) counts Source Versions, not sections: the parsed English ones Memory should hold, per company and for the bank, as `in_memory`, `all_skipped`, `triage_failed`, `in_flight` or `not_submitted`, with up to 20 samples of the last two (a version nothing submitted has no section, so sections alone show no gap); `atlas_versions_not_in_memory{company,reason}`, alert `AtlasVersionsNotInMemory`; HTTP 529 and `overloaded_error` text count as an outage that pauses the queue (`docs/decisions.md`, "Every parsed version reaches Memory").
- `scripts/memory-conformance.sh [--rehearse] [--only known-answers|behaviours] [--strict] [--base-url URL]` (memory-quality ticket 14; `atlas.conformance`, driver `tests/live/conformance.py`): Memory works as advertised, before anything is benchmarked (the precondition in `docs/evaluation-methodology.md` §10). Known answers on the live bank, read-only: `configs/memory/known-answers.yaml` (25 answers over the five probe questions, each with company, document, anchor or `null` (found from the sentence when run), its sentence, its hop and its bottleneck-test part; an answer that doesn't resolve is an error, not a miss), recall at 10 and 50 per question, hop and test part. Behaviours on a throwaway bank `atlas-conformance-<random>` (the gateway may delete only that prefix and `atlas-replay-`): the Lumentum and Coherent fixtures and the synthetic transcript retained through the real path, ten checks, each `passed`, `failed` with evidence, or `pending: ticket NN` (`--strict` fails on pending); at most 10 retain operations and 6 reflect/refresh/consolidation requests through counting proxies; the bank always deleted. `--rehearse` is the CI test `tests/integration/test_memory_conformance.py`; the live run (`tests/live/test_memory_conformance_live.py`) has the live suite's two locks. See `docs/runbooks.md`, "Memory conformance".
- `atlas jobs enqueue read_step --key K --payload '{"theme": "photonics", "question": "...", "step": "constraint", "company_ids"?: ["..."], "as_of"?: "..."}'`: the Reader (bottleneck-argument ticket 03; `atlas.roles.reader`, prompt `reader.v1`; `atlas.investigations.reader`) works one argument step (`constraint`, `demand_vs_supply`, `relief`, `control`, `capture`, `invalidation`) in its own run: a loop of role calls, each one action (`search_archive` over the companies' archive as of the time, `recall` across the theme at `ATLAS_READER_RECALL_MAX_TOKENS`, `read` a section's window, `record_fact` as a Fact with the quote placed as Claims are, `done`); a refused Fact comes back with its reason. Bounds `ATLAS_READER_MAX_CALLS` (12), `ATLAS_READER_MAX_PASSAGES` (40), the run's token budget; progress in `reader_session`; the job's artifacts list what it searched, recalled, read, recorded and was refused. Pausable, `minimax`. Rules in `docs/decisions.md`, "The reading agent".
- `atlas jobs enqueue extract_claims --key K --payload '{"source_version_ids": ["..."], "question": "..."}'`: the Investigator reads passages of those Source Versions and proposes Claims. The passages are chosen by `atlas.claims.selection` (memory-directed reading ticket 05; `docs/decisions.md`, "Passage selection: pointers and search, alternately"): the windows a term search (BM25) ranks highest for the optional question and the windows naming another known company, best first, with a floor of one passage for each periodic report, results release and results-call transcript (provider `tradingview`, type "Call transcript") and a ceiling per document (`ATLAS_INVESTIGATOR_MAX_PASSAGE_SHARE_PER_DOCUMENT`, a third of the passage budget; unused share passes on); a document with neither kind of window offers its lead windows. The job makes no recall. Each passage records every selection that chose it (`selected_by`: `search`, `entity:<id>`, `lead`; inside an investigation also `pointer:<query_index>`), and each Claim's read says which chose its passage (`passage_selected_by`). Then each quote is placed at the model's offsets or its one exact occurrence in the passage, if need be through a one-to-one fold of typographic hyphens, quotation marks and spaces (`offset_source` `model`/`located`/`folded`; several is `quote_ambiguous`; the stored quote is the archived text at the span), span-checked ones become Assertions, the rest are rejected with a reason. The Investigator's prompt is `investigator.v9` (its answer's twelve fields listed; pilot-fixes ticket 26). Every role's answer is checked by what it must contain: a field the response model doesn't name is dropped and recorded on the attempt (`ignored_fields` in `GET /api/v1/runs/{id}/role-calls`), never repaired; a missing or malformed one is repaired once, then quarantined; an Investigator Claim may leave out the object fields it doesn't need; repairs per role are in the run's role calls and the investigation's `usage.repairs` (`docs/decisions.md`, "Roles: an unknown field is ignored, a missing one repaired"). A quote names both parties, or leaves the filer unnamed in an impersonal sentence of its own document that names the other party or the product and no other company (`party_basis` `filer`, else `named`); `capacity_constrained` needs language of constraint, and `owns` runs from the holder to the issuer (`wrong_direction`). A `capacity_constrained` Claim may be **company-level** (memory-directed reading ticket 09; `Claim.company_level`): proposed with no object text, or with one that names no product ("our products", "manufacturing capacity"), it is accepted with no object and no layer when the subject is the filer of the document (`company_level_not_filer`), the quote carries a constraint cue and it names no other company (`other_company_in_quote`); the other three bottleneck predicates keep the named-object rule (rules in `docs/decisions.md`, "A company-level constraint needs no named product"). A Claim's layer is optional and kept only when a taxonomy term of that layer (`atlas.claims.LAYER_TERMS`) occurs in the object text or the quote; a word several layers share ("InP", "indium phosphide") supports none, and the accepted Claim then has no layer (`layer_reason` `layer_unsupported`; `layer_term` is the supporting word otherwise). In a call or conference transcript (source type `transcript`) a quote must be one speaker's words (`speaker_mixed`) and that speaker the company's own, by the paragraph's label "Name (Title, Firm)" naming the filer (`analyst_speaking` for "Analyst" or another firm, `speaker_unknown` for no label or no affiliation; `atlas.claims.speakers`, which the Skeptic's counterevidence uses too); an accepted transcript Claim records its `speaker`, shown on the Evidence tray (pilot-fixes ticket 22; `docs/decisions.md`, "Claim checks: an analyst's words are not the company's"). Rules in `docs/decisions.md`, "Claim checks" and "A layer only when the quote supports one". `GET /api/v1/claims` lists outcomes; `GET /api/v1/claim-extractions/{id}` (the job's artifacts name it) shows passages and progress. Needs LiteLLM and Hindsight; pausable.
- Counterparty companies (pilot-fixes ticket 05; `docs/decisions.md`, "Counterparty companies"): a Claim may name a company object outside the universe (`object_name`, the name as the quote writes it). With `ATLAS_SEC_USER_AGENT` set, extraction resolves it (SEC ticker file and submissions, GLEIF; exact normalized name, exactly one entity) and an accepted Claim creates a `counterparty` company (`Company.role`; audited), so the edge has both ends; otherwise the Claim is rejected `unresolved_company` or `ambiguous_company`. A counterparty is never ingested (`atlas ingest` refuses it) and never an investigation seed; it shows on the edge table, the theme map (`counterparties`) and its dossier; `GET /api/v1/companies?role=researched|counterparty` filters. The owner promotes it by adding it to the theme config or committing its Candidate.
- `atlas jobs enqueue review_relationships --key K --payload '{}'` (or `{"assertion_ids": [...]}`): machine-review Assertions into Relationships (typed, directed edges, identified by subject, predicate and object; layer-tagged only when their Evidence names a layer). Deterministic checks (verbatim span, Tier A, unhedged directional language) plus the Reviewer role's answers (`reviewer.v5`: direction, hedge and layer, each on its own; no layer answer is needed for an edge with none) make an edge `machine_reviewed`; anything else goes to the exceptions queue (`needs_human_review`); co-mention forms no edge. Evidence that brings another layer than its edge has joins it with `layer_conflict` (the edge goes to the queue) instead of making a second edge; an edge with no layer takes the first layer later Evidence brings. A company's own `capacity_constrained` statement that names no product forms its **company-level edge** (`Relationship.company_level`: no object company, no object text, no layer; the reserved empty `object_key`, so one per company, and every further such Assertion adds Evidence to it); a risk factor's "could" is a Claim but never machine-reviewed (`hedged_language`). It is in the edge table, on the company's dossier and on the theme map under its company. `GET /api/v1/relationships?layer=&review_state=&predicate=&company_id=&sort=&order=` is the edge table (Evidence and family counts; `layer=none` is the edges with no layer), `GET /api/v1/relationships/exceptions` the queue, `GET /api/v1/relationships/layer-duplicates` the read-only report of edges recorded before migration 0055 that differ only by layer (left as they are), `GET /api/v1/relationships/{id}` an edge with its Evidence spans, `POST /api/v1/relationships/{id}/review` the owner's approve/reject (audited). Needs LiteLLM and Hindsight; pausable.
- `GET /api/v1/themes` and `GET /api/v1/themes/{id}/map` (the Theme explorer: each theme's companies by layer with coverage gaps, the Relationships between them (those with no layer under their companies, not under a layer), its Candidates, and the Bottlenecks mental model's open gaps with a `status` when absent) and `GET /api/v1/companies/{id}/dossier?as_of=` (the Company dossier: identity and listings, pending identity reviews, themes, Source Documents, Relationships out and in, as-of financials, fetch-gate blocks). Pages `frontend/app/themes/`, `app/theme/` and `app/company/`.
- `uv run atlas hindsight apply-template`: dry-run, then import `configs/hindsight/bank-template.json` into the research bank, recording its version. A mental model whose trigger could run away or read another model (no explicit `refresh_after_consolidation: false`, no explicit `refresh_cron: null`, no minimum interval, no `exclude_mental_models: true`) makes the template invalid: Atlas's daily job is the only scheduler (template 1.3.0; the models are tagged `theme:photonics`, keep their trace, and reflect's own recall returns no raw chunk and shows observations' source facts; `docs/decisions.md`, "Reflect and the models: grounded and counted"). A bank without `enable_auto_consolidation: false` makes the template invalid too (template `1.4.0`; memory-quality ticket 19), and so does one that leaves out, or nulls, a server default Atlas relies on, pinned at its 2026-10-03 value: recall's temporal, graph, keyword and rerank arms, `store_document_text`, `entities_allow_free_form`, `retain_extraction_mode` (`concise`), `retain_chunk_size` (3000) and `consolidation_max_memories_per_round` (100), or one of the four overrides once set on the bank outside the template (`consolidation_llm_batch_size` 8, `consolidation_source_facts_max_tokens` 4096, `…_per_observation` 256, `max_observations_per_scope` -1) (template `1.5.0`; memory-quality ticket 23; `docs/decisions.md`, "The bank template pins what Atlas relies on").
- The bank template's missions and layer label (memory-quality ticket 05; `docs/decisions.md`, "The bank template's missions and the layer label"): `retain_mission` has an ignore list (safe-harbor, certifications, exhibit lists, signature blocks, generic risk language) and attributes each statement to who made it; `observations_mission` stands alone (it replaces Hindsight's built-in rules); `entity_labels` has one group, `layer`, whose values are the Claim layer taxonomy's (`atlas.claims.LAYERS`; a unit test fails when they differ), `tag: true`, so a recall can be scoped by `layer:<value>`. The fake's `script_fact_labels` gives a derived fact its labels. `uv run python spikes/hindsight/mission_compare_05.py [--show]` compares the old and new missions with `dry-run-extract` on the local spike Hindsight (≤ 12 LLM requests; live, so the lead's to run).
- `uv run atlas memory consolidate [--key K] [--backfill]` (memory-quality ticket 19): Atlas decides when Memory consolidates, since the template turns Hindsight's automatic consolidation off. The same transaction freezes the version's Research Snapshot: canonical JSON at `archive://snapshots/sha256/<hex>` and an insert-only `research_snapshot` row. `GET /api/v1/snapshots[?hypothesis_id=]` lists them, and `GET /api/v1/snapshots/{id}` re-hashes the archived object on every read (500 `snapshot_integrity_failed` if it was altered or is missing). Metric `atlas_research_snapshots_total`; contents in `docs/decisions.md`, "The publish gate and Research Snapshots".
- Proposed updates (§5.7 contradiction flow): publishing records the version's dependencies (`hypothesis_dependency`). A dependent Assertion reviewed disputed/rejected/superseded, the owner's rejection of a dependent Relationship, a new Source Version of a cited document that no longer contains a cited quote, or an accepted independent Skeptic contradiction of the same span (never bear context) enqueues the deterministic `check_contradictions` job (not pausable), which flags each Hypothesis's latest published version with one `proposed_update` per event (Evidence, affected findings, concerned Candidates). `GET /api/v1/hypotheses/{id}/proposed-updates`, `GET /api/v1/proposed-updates[/{id}]?hypothesis_id=&candidate_id=&state=`, `Hypothesis.open_proposed_updates`; the owner's `POST /api/v1/proposed-updates/{id}/accept` (`{note?}`: a new draft correction, affected findings `needs_review`) or `/dismiss` (`{reason}`), audited. The published version and its snapshot never change. Rules in `docs/decisions.md`, "Proposed updates".
- `POST /api/v1/replay-jobs` (`{"cutoff", "company_ids"?, "question_set"?, "max_source_versions"?}`), `GET /api/v1/replay-jobs[/{id}]`, `POST .../{id}/cancel`: a replay (§9.2). The `replay` job (pausable, `codex`-budgeted, one step per attempt) creates `atlas-replay-<id>` on the **local** Hindsight (`ATLAS_REPLAY_HINDSIGHT_URL`; 503 without it) from the bank template without mental models, re-retains only the Source Versions available at the cutoff (at most `ATLAS_REPLAY_MAX_SOURCE_VERSIONS`, the latest; every section, triage bypassed) oldest first, waits for consolidation (bounded), asks the fixed question set (`configs/replay/question-sets.yaml`: recall + reflect, scoped like production research, citations resolved against the replay's own `replay_document` ledger), records leakage (`future_accepted` must be 0) and always deletes the bank, also on failure or cancel. Rules in `docs/decisions.md`, "Replay banks"; the opt-in live run in `docs/runbooks.md`, "Replay banks".

## Conventions

- Test-first at agreed seams only; test behavior through public interfaces, never internals. Real Postgres, never SQLite.
- Settings are `ATLAS_*` env vars (or `.env`), validated at startup. Optional providers log `<provider> disabled: missing <VAR>` once.
- Ruff and strict pyright must be clean; TypeScript is strict.
- Record each ticket's files, tests and results in `docs/implementation-log.md`. Never claim a live integration was tested when only fixtures were.
