# Atlas Research: agent guide

Evidence-driven investment research platform built around Hindsight. Start with `START_HERE.md`; the authoritative spec is `hindsight_investment_research_build_plan.md` (v1.1).

**Current effort:** the pilot review. Orient at its map, `.scratch/atlas-pilot-review/map.md`, before choosing work: take the first open, unblocked ticket, and put new work in the map, not in a log entry's "Next" line.

**Roadmap planning:** when revisiting priorities or specifying the post-pilot effort, read [the 4 October roadmap proposal](docs/research/proposed-roadmap-2026-10-04.md), preserved at the owner's request. It proposes sequencing changes; the pilot map remains the execution authority until accepted changes are recorded there.

## Commands

- `scripts/ci.sh [static|suite] [--no-image]`: the one CI entrypoint (GitHub Actions runs exactly this): `static` (lint, types, frontend unit tests, API client; no Docker) runs on GitHub's runners, then `suite` (Compose services, pytest, e2e, image) on the self-hosted scale set; no argument runs both. `--no-image` skips the image build. Main requires the `ci` job (green only when both stages are); `docs/deployment.md`, "CI".
- `uv run pytest`: unit tests (network blocked by pytest-socket) and integration tests (localhost only; needs `docker compose up -d --wait postgres-app silo`).
- `uv run atlas api | worker [--once] | migrate`: the three roles of the one image.
- `uv run atlas mcp`: the Atlas MCP server (atlas-beliefs ticket 15; `atlas.mcp`; `docs/decisions.md`, "The Atlas MCP server"): the research session's tools over the existing `/api/v1` routes, streamable HTTP at `POST /mcp` (mounted under the API unless `ATLAS_MCP_ENABLED=false`; `atlas mcp` serves the same app on `ATLAS_MCP_PORT`, 8001; an `Origin` header must be in `ATLAS_MCP_ALLOWED_ORIGINS`; no authentication of its own, like the API). Eighteen tools, typed (six more below): `open_session`, `close_session`, `companies`, `search`, `read`, `locate`, `record_fact`, `get_fact`, `judge_statement`, `relate_facts`, `propose_belief`, `cite_belief`, `supersede_belief`, `open_issue`, `narrow_issue`, `complete_issue`, `next_issue`, `recall`. Every tool but `open_session`, `companies` and `next_issue` carries the research session's `session_id`; **the session's as-of time is the session row's, no tool takes one**: `search` passes it to the archive search, `recall` as `available_by`, and `read`, `locate`, `record_fact`, `get_fact`, `judge_statement`, `relate_facts`, `propose_belief` and `cite_belief` refuse a Source Version (or a Fact of one) public after it (`available_after_as_of`, `fact_available_after_as_of`). Quotes are located server-side (`atlas.mcp.locate`, the typographic fold; none or several occurrences refused), companies are named by slug, and `propose_belief` answers a `joins_dated_documents` warning (never a refusal) when its supporting Facts' documents are more than 90 days apart and the statement does not name each year. A refusal or error is an `isError` result (`refused` + code, or `error`); an unknown or closed session is `unknown_session`/`session_closed`. Each call on a session is recorded after its outcome in the insert-only `session_tool_call` (migration `0109`; `ok`, `refused`, `error`), and `GET /api/v1/sessions[/{id}]` gives `tool_calls`, Atlas's count of the session's calls, and what the session did (ticket 31; read side only): `agent` (`scout`, `researcher`, `skeptic`, `editor` or `lead`: a pipeline session is `lead`; a Claude session is the agent its actor names alone, with an optional `atlas-` before and `-agent` or `-routine` after, which is what the scheduled routines pass since ticket 29b, else, for older sessions, the one its question opens with, `Scout:`, `Skeptic:` or `Editor:`; any other `lead`), `beliefs_proposed`, `beliefs_examined` (`confirmed`, `qualified`, `contradicted`, `nothing_new`) and `issues_opened`, counted in the list's one query. A tool returns text only with its span (`read`'s window and offsets, `search`'s passages); `recall` is labelled an index, never Evidence. `.claude/skills/atlas-research/SKILL.md` names the tools; `atlas_tools.py` is the older client, kept. The agents' tools (ticket 16; `atlas.mcp.agents`), each a projection of one route and bound by the session's as-of time: `newest_documents` (`GET /archive-documents`, the documents the archive search searches, newest first, `since` and `kinds`), `list_beliefs` and `get_belief` (`GET /beliefs[/{id}]`; a Belief whose own `as_of` is after the session's is not listed and is refused, a citation of a later document is left out), `list_issues` (`GET /issues`), `draft_hypothesis` (`POST /hypotheses`, the Belief-backed draft, cutoff = the session's as-of time) and `get_hypothesis` (the Hypothesis, its latest version's steps and `GET .../publish-gate`); there is no publish and no judge tool. Their prompts beside the Researcher's: `scout.md` (the theme's newest documents for bottleneck cues: a `context` Fact and a `question` Issue each, about 60 calls), `skeptic.md` (a proven Belief: what would falsify it, counterevidence Facts related and cited, narrowed or flagged, never judged, about 80 calls) and `editor.md` (a draft from the proven Beliefs and a report of what blocks publishing, never publishing, no market-expectations paragraph, about 25 calls). Tests `tests/integration/test_mcp_server.py`. **Isolated sessions** (atlas-beliefs ticket 29a, the early-call scorecard; migration `0116`; `docs/decisions.md`, "Isolated sessions for the scorecard"): `open_session` (and `POST /api/v1/sessions`) take `isolated: true`; Atlas then answers `GET /research/prior-work` with nothing for that session, never reuses a Fact it records (nor sets `same_span_as`), refuses `recall` with `bank: beliefs`, `list_beliefs`, `get_belief`, `examine_belief`, the Issue tools, `draft_hypothesis` and `get_hypothesis` (`isolated_session`), answers `recall` of the research bank with facts only (no observation; each section public by the as-of time), creates no Issue when it closes, refuses another session's Facts (`fact_not_in_session`) and Beliefs (`belief_not_in_session`), raises no Belief notice, and refuses `POST /beliefs/{id}/judge` on its Beliefs (409 `isolated_session_belief`: no call, no conclusions bank). The routes take the session where they can (`session_id` on `/memory/recall`, `/statements/judge|relate`, `/issues`, the Belief cite and supersede). `GET /api/v1/sessions/{id}/tool-calls` lists a session's recorded calls in order. The `scorecard` theme (SanDisk, IREN, eToro, Snap, POET) is never a scheduled agent's.
- Scheduled agents (atlas-beliefs ticket 17; `agent/`; `docs/decisions.md`, "Scheduled agents run in the cluster"; `docs/runbooks.md`, "Scheduled agents"): the image `ghcr.io/ekenheim/atlas-agent:X.Y.Z` (released beside `atlas` with the same tags; `agent/Dockerfile`, pinned Node and `@anthropic-ai/claude-code`, non-root, read-only root, `HOME=/tmp`) runs headless Claude Code on the owner's subscription (`CLAUDE_CODE_OAUTH_TOKEN` from `claude setup-token`, in a Secret the owner creates) against the in-cluster MCP URL (`ATLAS_MCP_URL`). `agent/run.sh <scout|researcher|skeptic> [--dry-run]` fills `agent/prompts/<agent>.md` (theme `ATLAS_AGENT_THEME`, as-of = the run's start, output folder `/tmp/out`, call bound; each wrapper names its skill prompt, sets no judgement and publishes nothing, and has a `Tools:` line), calls `claude -p` with `--strict-mcp-config`, `--tools Read,Write,Edit,Glob` and `--allowedTools mcp__atlas ...` (no shell), prints one JSON line (agent, `ok`, session id, turns, cost, duration, the result's first 2,000 characters; the token cut from everything) for the pod log and exits non-zero unless the run succeeded. The cluster's CronJobs are the lead's, in home-ops. `tests/unit/test_agent_routines.py` fails when a tool a wrapper or a skill agent prompt lists is not on the server's `tools/list` (and `tests/unit/test_agent_run.py` runs `run.sh` under a stand-in `claude`); `scripts/ci.sh static` runs both, `suite` builds and smokes the image (`scripts/agent-image-smoke.sh`). The early-call scorecard's runs (ticket 29b) go through `agent/scorecard-run.sh`, which runs the next unrun entry of `agent/scorecard/runs.json` as an isolated session that `run.sh` itself opens before `claude` starts (twelve tools, no `open_session`; `docs/decisions.md`, "Isolated sessions for the scorecard"; `docs/runbooks.md`, "Scorecard runs"). The Researcher alone takes `ATLAS_AGENT_QUESTION` (verbatim, replaces `next_issue`), `ATLAS_AGENT_SEEDS` (slugs) and `ATLAS_AGENT_ISOLATED=true` (ticket 29a: the prompt has it open an isolated session, and `--allowedTools` is the thirteen tools of the isolated list, not the whole server; the summary line's `atlas_session_id` is matched by as-of time, question and seeds); the scorecard's runs pass the exact model ID in `ATLAS_AGENT_MODEL` (`docs/runbooks.md`, "Scorecard runs"). `agent/run.sh watch` (Chokepoint Watch ticket W2; `agent/prompts/watch.md`, `docs/runbooks.md`, "The Chokepoint Watch") is the weekly Watch agent of one theme: `ATLAS_AGENT_THEME` and `ATLAS_WATCH_DEMAND_DRIVER` required, `ATLAS_WATCH_MODE` (`architect`|`delta`) and `ATLAS_WATCH_SINCE` (a date) asked of `GET /api/v1/watch-runs?theme=&limit=1` when unset (a dry run with both given asks nothing), 60 calls, allowed exactly the prompt's `Tools:` line; the isolated researcher's dry run and the other agents' are unchanged (`tests/fixtures/agents/`, `tests/fixtures/scorecard/`).
- `uv run atlas audit verify`: check the audit hash chain; exits 1 if it is broken.
- `uv run scripts/provision_archive.py --endpoint <url>`: the owner's one-off archive bucket/user provisioning (root credentials from `MINIO_ROOT_USER`/`MINIO_ROOT_PASSWORD`; see `docs/runbooks.md`).
- `uv run atlas companies seed`: create or update the companies in `configs/themes/ai-infrastructure.yaml` (19 companies in two themes: the 12-company `photonics` universe and the seven SEC-path seeds of `memory-packaging`, each with its layer, which is its theme's, and source path; idempotent). A theme's layers are free slugs (`^[a-z][a-z0-9-]{1,40}$`) its config declares, each with a `covers` text, and a company's `layer` must be one of its theme's (refused at load naming company, layer and theme); a theme that lists none has photonics' seven; the database checks only the slug format (migration `0119`); `atlas.claims.LAYERS`, the Claim taxonomy, and the bank templates' `layer` labels are unchanged (Chokepoint Watch W6a; `docs/decisions.md`, "A theme's layers are its config's"; test theme `tests/fixtures/themes/free-layers.yaml`).
- `uv run atlas companies resolve [--company <slug>]`: seed, then resolve each company to its CIK, LEI and listings through SEC's ticker file and submissions, GLEIF and OpenFIGI (keyless; needs `ATLAS_SEC_USER_AGENT`; live calls, so never in tests). Exact and corroborated identifiers commit (a listing gains its composite and share-class FIGIs and segment MIC); the rest, and every CIK↔LEI link, wait for the owner: `GET /api/v1/identity-mappings?review_state=pending`, `POST /api/v1/identity-mappings/{id}/confirm|reject` (audited). `atlas.identity.service.resolve_mention` resolves a mention (name, ticker + MIC, CIK, LEI, ISIN) against the universe first (rules in `docs/decisions.md`, "Entity resolution").
- `uv run atlas ingest --company <slug> [--key K]`: enqueue an ingest job; `atlas worker --once` runs it. It dispatches on the company's source path: `sec` (recorded fixtures exist for `lumentum` and `coherent`), or `exchange:hkex` (Innolight via HKEXnews: every request passes the fetch gate (the site register `configs/sources/sites.yaml`, the terms, robots.txt); HKEX's Terms of Use forbid automation, so without an IIS licence or written consent recorded it records a `blocked` gate decision and fetches nothing; `ATLAS_EXCHANGE_FIXTURES_DIR=tests/fixtures/hkexnews` replays hand-written fixtures, `ATLAS_EXCHANGE_LIVE=true` with `ATLAS_EXCHANGE_USER_AGENT` goes live; `GET /api/v1/companies/{id}/fetch-gate-decisions?status=blocked` lists blocks), or `exchange:fca-nsm` (IQE via the FCA National Storage Mechanism, allowed by its terms, through the same gate at 0.5 requests/s; fixtures in `tests/fixtures/fca-nsm`; LSE RNS and IQE's Brighter IR iframe are blocked in the register), or `exchange:amf` (Soitec via the AMF info-financière open API, Licence Ouverte, credited in each version's `metadata.announcement.attribution`; the register's `api_client` lets the documented API and its file links through although robots.txt disallows them for crawlers; French-only documents are archived, not retained; fixtures in `tests/fixtures/amf` (`scripts/make_amf_fixtures.py`); Euronext and soitec.com are blocked in the register). Fixture mode needs `ATLAS_SEC_FIXTURES_DIR=tests/fixtures/edgar`; `ATLAS_SEC_LIVE=true` fetches from SEC. With `ATLAS_HINDSIGHT_URL` set (and the template applied), each new parsed Source Version is then retained; `GET /api/v1/source-versions/{id}/memory` shows its sections. Each retain item (research, replay and evaluation banks alike) sends explicit `observation_scopes`, one per theme tag and no company scope, so observations consolidate across a theme's companies and documents; a company-scoped recall therefore returns facts and no observation (`docs/decisions.md`, "Observation scopes: one per theme"). `atlas jobs enqueue retain --key K --payload '{"source_version_id": "..."}'` retains one by hand. Add `--backfill` (to `ingest` or `jobs enqueue`) to make it backfill class: it and its retains run only in `ATLAS_BACKFILL_WINDOW` if one is set (comma-separated ranges; default empty: any time) and never use the budgets' interactive reserve. LLM-backed kinds are held by their provider's rolling 5 h budget (`codex`: Hindsight operations submitted, `ATLAS_CODEX_BUDGET_OPERATIONS`; `hindsight_consolidation`: the research bank's consolidation rounds, `ATLAS_CONSOLIDATE_BUDGET_ROUNDS`; `minimax`: role-call tokens, `ATLAS_MINIMAX_BUDGET_TOKENS`; a budget of 0 holds the provider, 1 does not; `docs/runbooks.md`, "Universe rollout and quota budgets"). `ATLAS_RETAIN_EXTRACTOR=minimax` (unset by default) makes every retain item ask the shared Hindsight for its MiniMax extractor (`extractor: minimax` in the item's metadata; Hindsight's metadata routing; replay banks and evaluation banks send it too); `retain`, `poll_operation` and `reprocess` then spend their own budget, `hindsight_minimax` (`ATLAS_RETAIN_BUDGET_OPERATIONS`, 200 operations per window), and `codex` keeps `reflect`, `refresh_mental_model` and `replay`; the extractor asked for is recorded per section and operation (`extractor` in the memory read; null: the primary). Rules in `docs/decisions.md`, "Atlas's retains on MiniMax by metadata routing"; switching it on and back in `docs/runbooks.md`, "Retains on MiniMax". A company's first backfill ingest records an ingest plan (`GET /api/v1/ingest-plans`); `--max-retains N` retains at most N not-yet-retained versions, newest first (a rerun takes the next N). A 429 or outage pauses the Hindsight job kinds with backoff (≤ 1 h); `GET /api/v1/queue` shows the pause, the window and pending jobs by kind.
- `GET /api/v1/companies/{id}/financials?as_of=&metric=` (canonical metrics from `configs/financials/metrics.yaml`, derived quarters included), `GET /api/v1/companies/{id}/financial-observations?as_of=` and `GET /api/v1/financial-observations/{id}` (with its restatement history): as-of XBRL financials. Each ingest normalizes the company's latest companyfacts Source Version once, whether or not that run fetched it; `uv run atlas financials normalize [--company <slug>]` does so without an ingest (the backfill for versions recorded before normalization; `docs/runbooks.md`, "XBRL normalization backfill"); every fact takes its filing's `available_at` (rules in `docs/decisions.md`, "XBRL normalization"). A failed normalization doesn't fail the ingest: it is recorded in `financial_normalization_failure` (audited; the job's `financial_normalization` artifact has `status: failed`; `atlas_financial_normalizations_total{outcome}`) and retried by the next ingest.
- Mechanical bear checks (Chokepoint Watch ticket W4; `atlas.bear_checks`; `docs/decisions.md`, "The mechanical bear checks"): `GET /api/v1/companies/{id}/bear-checks?as_of=` (default now; deterministic, no model call) answers six checks over what Atlas holds, each `{key, status: flag|clear|unknown, value, basis, sources}`: `dilution` (dei cover count, else balance-sheet count, against 12 months earlier; flag above +10%; a split-like ratio uses the split-adjusted weighted diluted shares or is `unknown`, and several share classes are `unknown`), `shelf_or_atm` (an S-3, S-3ASR, F-3, S-1 or 424B5 in the ledger in the 365 days before as-of flags; Atlas ingests only 10-K, 10-Q and 8-K, so an empty ledger is `unknown`, basis "form not ingested", never `clear`), `gaap_gross_margin` (trailing four quarters from XBRL, GrossProfit else revenue less cost of revenue, against the four a year earlier; flag below 0 or a fall of more than 5 points; no prior year is `unknown`), `customer_concentration` (the latest 10-K or 20-F public by as-of: sentences like "accounted for approximately N% of our net revenue" that name a customer and not a region, and the rows of a customer revenue table, by the current period's share (never the largest; "more than 10%" is a lower bound, "our ten largest" is `top_customers_share`); flag at N >= 25; `clear` only from a stated share below 25% or "no single customer accounted for more than N%" in a whole parse, else `unknown`; `atlas.bear_checks.patterns`), `going_concern` ("substantial doubt about our ability to continue as a going concern" in the latest 10-K, 10-Q, 20-F or 40-F; only an actual denial is not a flag; `clear` only from a whole parse) and `net_cash` (cash and short-term investments less debt at the latest balance sheet with both; flag for net debt; debt is the distinct debt concepts tagged, each named in the basis, and `unknown` when totals cannot be told from parts or debt is not tagged). A series older than 15 months at as-of is `unknown`. `sources` are XBRL observation ids (`GET /financial-observations/{id}`) or a Source Version with the sentence's `char_start`/`char_end` in the named `parser_version`. MCP `bear_checks(session_id, company)` is the same answer as of the session's time (no as-of argument); refused in an isolated session (`isolated_session`), so the early-call scorecard's frozen surface is unchanged (`REFUSED_SERVER_SIDE_SINCE_0_6_14` in `tests/unit/test_agent_run.py`). Tests `tests/unit/test_bear_check_patterns.py`, `tests/integration/test_bear_checks.py`.
- What a retained section says (memory-quality ticket 04; `docs/decisions.md`, "What a retained section says"): each retain item (production, replay and evaluation banks alike) carries a context built by `atlas.retention.context.section_context` (whose document, what kind and form, the period, the day it became public, the section, and who speaks: the filer; on a call transcript management and analysts, an analyst's question not the company's statement; on a manual import the publisher), `entities` (the filer's canonical name and every universe company or counterparty the section's text names, by passage selection's matcher, as written, `resolve_entities: false`) and display metadata after the provenance keys (`company_name`, `form`, `period`). Each memory document records the `retain_profile` (`retain-v2`; `retain-v1` before migration 0062), `retain_context` and `retain_entities` it was submitted with; `GET /api/v1/source-versions/{id}/memory` shows them and `current_retain_profile`. Stored sections reach a new profile only by the backfill (ticket 12).
- `uv run atlas sources import --company <slug> --file <path> --origin-url <URL> --published-at <ISO time with offset> [--title T]`: record a document the owner downloaded by hand (e.g. from HKEXnews, which Atlas may not fetch) as a `manual_import` Source Version, `available_at` = the given publication time (`publisher_timestamp`); parsed, put in its Evidence Family, retained if English, audited; the same bytes again change nothing.
- Primary sources beyond filings (Chokepoint Watch W3 phase 1; `atlas.ledger.web_fetch`, `atlas.discovery.adhoc`, `atlas.mcp.watch_sources`, `atlas.sources.web_dates`; `docs/decisions.md`, "Primary sources beyond filings"; `docs/source-licenses.md` §6.1 for adding a site): `uv run atlas sources fetch --company <slug> --url <URL> [--published-at <ISO time with offset>] [--session-id <UUID>]` and `POST /api/v1/sources/fetch {company, url, published_at?, session_id?}` (synchronous, no job) fetch one HTML or PDF page into the archive as a Source Version of provider `web`, `source_type` `web_page`. Every request, each redirect hop included, passes the fetch gate: the site must be in `configs/sources/sites.yaml` with `automation: allowed` (or a recorded consent) and robots.txt must allow the path; otherwise a `blocked` gate decision is recorded and nothing is fetched (403 `fetch_blocked` with `blocked_by` `register`/`terms`/`robots`; the CLI prints it and exits 1). Tier A (`public_issuer`) when the register's `own_site_of` names the company, else B (the site's `license_class` in the register, else `third_party`); a URL already fetched for another company is refused (`url_belongs_to_other_company`, 409). The gate comes before the client, so a blocked URL is recorded even when fetching is off. `available_at`: the `published_at` given (basis `publisher_timestamp`, `date_source` `argument`), else the page's own date (`article:published_time`, or JSON-LD `datePublished` of an Article, NewsArticle or PressRelease; never a bare `<time>`), only when it is no later than the fetch and at most 7 days before it (basis `page_published_date`, migration `0120`; a date without an offset is read at UTC-12, a date alone as the end of that day there), else the fetch time (`observed_discovery`, `fetch_time`), the page's other date kept in `metadata.web.date_as_written`; a PDF has none. A web Source Version is readable by a session when `available_at <= as_of` and `fetched_at <= as_of`, or when the session fetched it (`fetch_observation.session_id`) and is prospective (not isolated, its as-of within 36 hours before the fetch); an isolated session sees no web version at all (`read`, `locate`, `record_fact`, `get_fact`, `search`). The same bytes again: `unchanged`; a 304: `not_modified`; changed bytes: a new version available from the fetch (`observed_revision`). It joins its Evidence Family and is retained if English. Live only with `ATLAS_EXCHANGE_LIVE` (generic User-Agent, the site's rate), else it replays `ATLAS_EXCHANGE_FIXTURES_DIR/<slug>/manifest.json` (fixtures `tests/fixtures/web/`); with neither, 503 `web_fetch_off`. `GET /api/v1/web-search?q=&theme=&session_id=&published_by=&limit=` (SearXNG, engines and language from settings) and `GET /api/v1/filing-search?q=&forms=&start=&end=&theme=&session_id=&limit=` (EDGAR full-text search over every filer, SEC User-Agent and rate limit; default window the year to today) store their results as `searxng` and `edgar_fts` leads (one per canonical URL, as a discovery's; a `discovery_query` with no discovery, migration `0120`) and return them with their lead ids. MCP (additive; each refuses an isolated session first, `isolated_session`, and none is named in the frozen isolated prompt): `filing_search(session_id, query, forms?, start?, end?, limit?)` (`end` clamped to the last EDGAR filing day certainly over at the session's as-of instant, a window starting after it refused `window_after_as_of`), `web_search(session_id, query, limit?)` (results whose date could still be running at the as-of instant left out), `fetch_page(session_id, company, url)` (passes its session; `readable: false` when the page's `available_at` is after the as-of time: recorded, but `read` refuses it). Leads are never Evidence. Tests: `tests/integration/test_web_sources.py`, `test_mcp_watch_sources.py`, `tests/unit/test_web_sources.py`.
- Retention triage (`ATLAS_RETENTION_TRIAGE=auto|on|off`; `auto`, the default, is on when LiteLLM is configured): a new version's `retain` first runs a `triage` job (`minimax`, pausable). It inherits the decisions of unchanged sections (content hash) from the predecessor version, skips boilerplate Item headings by rule, and asks the Triage role (rubric `backend/atlas/roles/prompts/triage.v3.md`, in up to `ATLAS_TRIAGE_WINDOWS_PER_SECTION` (10) windows per section) about the rest; exhibit indexes go to the role, not the rules (`triage-rules-v2`). Only `retain` sections go to Hindsight; skipped ones stay archived and citable. `GET /api/v1/triage?source_version_id=&company_id=&decision=&category=&method=&effective=` lists decisions (insert-only, audited). `POST /api/v1/source-versions/{id}/sections/{anchor}/retain` (`{reason, investigation_id?}`) retains a section on demand. A failed triage retains nothing: it is held or retried, and a job failed after its attempts is re-enqueued by `uv run atlas triage retry --source-version <id> | --failed` (gauge `atlas_triage_failed_jobs`). Windows overlap by `ATLAS_TRIAGE_WINDOW_OVERLAP_CHARS` (200). Rules in `docs/decisions.md`, "Retention triage".
- `uv run atlas triage audit [--sample N] [--company slug] [--seed S] [--backfill] [--wait]`: measure triage's misses (ticket 33). It draws a seeded sample of sections whose effective decision is `skip`, stratified by form and length band, and enqueues a `triage_audit` job (`minimax`, pausable, a few samples per attempt). The job gives each sample's archived parsed text, whole, to the full-section judge (role `triage_judge`, prompt `triage_judge.v2`: rubric v3's criteria; overlapping chunks only past `ATLAS_TRIAGE_JUDGE_MAX_CHARS`, 60,000, retained if any chunk is) and stores one insert-only `triage_audit` row per sample. `GET /api/v1/triage/audits[/{id}]` reads the audits with the summary: the miss rate with a Wilson 95% interval, by length band, category, method and form, and example misses with the anchor and the judge's reason. `--wait` prints the summary once the worker is done. See `docs/runbooks.md`, "Triage audit".
- `uv run atlas retention retry-failed [--since D | --all-history] [--error-class C]... [--company <slug>] [--interactive]`: re-enqueue (backfill class by default; audited) the sections not in memory. A section's outcome comes from its own Hindsight document whatever its operation's end (memory-quality ticket 03): stored with facts is `completed`, with none `zero_fact` after one reprocess, absent `cancelled` when the owner cancelled the operation (a state of its own, not a failure; migration `0068` moved the recorded cancellations there) or `failed` with a class (`permanent`, `transient`: a timeout or relayed 5xx, resubmitted with the queue's backoff up to `ATLAS_RETAIN_TRANSIENT_RETRIES` times, or `missing`). ## Conventions

- Test-first at agreed seams only; test behavior through public interfaces, never internals. Real Postgres, never SQLite.
- Settings are `ATLAS_*` env vars (or `.env`), validated at startup. Optional providers log `<provider> disabled: missing <VAR>` once.
- Ruff and strict pyright must be clean; TypeScript is strict.
- Record each ticket's files, tests and results in `docs/implementation-log.md`. Record each experiment (a hypothesis, how it was measured, the result, kept, reverted or parked) in `docs/experiments.md`, the index of what has been tried. Never claim a live integration was tested when only fixtures were.

### Building, releasing and the pilot

- `docs/agents/implementer-brief.md`: what the lead hands each implementer agent (test-first at the seams, local checks only, commit and report; the lead pushes and runs the runners).
- `release-atlas` (skill): integrate ticket branches, chain migrations, release a tag and open the home-ops PR; the owner merges.
- `pilot-review` (skill): run a pilot investigation on production and review every accepted Claim against its span; results in `.scratch/pilot/results.md`, defects as tickets.
- `atlas-research` (skill, `.claude/skills/atlas-research/`): a Claude session researches a bottleneck question with Atlas's tools (`atlas_tools.py`: as-of archive search, read, locate, record a Fact through `POST /api/v1/facts`, recall filtered to sections available by the as-of time) and writes the argument with Beliefs; the method since the owner's revision of 2026-10-12 (`.scratch/atlas-beliefs/spec.md`; proof in `.scratch/pilot/results.md`, "The proof sessions"). The role pipeline is the bulk mode.
- `/api/v1/beliefs` (atlas-beliefs ticket 02; `atlas.beliefs`, ADR 0003): Beliefs. `POST /beliefs` proposes one (statement, theme, step, companies, `as_of`, `session_id`, citations of Facts or Assertions with a signed `valence` or a counter-judge `relation` (contradicts -1, limits/dates -0.5, qualifies -0.25, supports +0.5) and a weight; refused `no_load_bearing_citation` without a load-bearing citation of positive valence; born `unproven`), `POST .../{id}/cite`, `POST .../{id}/judge` (`actor` required; insert-only history; clears the open flags), `POST .../{id}/supersede` (`by`, `reason`; the old Belief keeps its citations and history), `GET /beliefs?theme=&step=&company_id=&judgement=&status=&flagged=&as_of=` (`as_of`: the judgement current then) and `GET /beliefs/{id}` (citations with quote, span and date, counterevidence, flags, history, supersession, session); a Belief summary carries `newest_evidence_at`, the latest effective `available_at` among the Source Versions of its supporting citations (load-bearing weight, positive valence), which `get_belief` over MCP recomputes from the citations the session may see (ticket 31). Flags (`belief_flag`, raised by code in the proposed-updates trigger path, cleared only by a judgement): `assertion_reviewed`, `fact_superseded`, `source_revised` (the `check_contradictions` job finds the revised version's parsed text lacks the quote) and `counterevidence_stands` (a load-bearing citation at valence <= -0.75 whose Fact stands). Every write is audited (`belief.proposed|cited|judged|superseded|flagged`). Pages `frontend/app/beliefs/` (by step and judgement; filters in the URL) and `app/belief/`; the skill's tool has `belief propose|cite|supersede`. Judged where written down (ticket 23; `atlas.judging`, `ATLAS_FACT_STATEMENT_JUDGE` `sessions`|`always`|`off`; `docs/decisions.md`, "Statements are judged where they are written down"): a Fact recorded with a `session_id` (every Fact under `always`, the pipeline's Readers too) has its statement judged against its own quote by the finding judge (`finding_judge.v4`; `ATLAS_FACT_STATEMENT_JUDGE_VOTES` votes, default 1, decided by the finding judge's rule) after the other checks: misstated is 422 `statement_beyond_quote` (the error's `detail` has `beyond`, `kinds`, `reason`), supported is stored (`statement_judgement`), an unreachable judge stores it `unjudged` and never blocks; `POST /sessions/{id}/close` judges the card's `thesis` against the Facts its statements cite, as a thesis (`finding_judge.v5`, ticket 24), and stores the verdict as the card's `thesis_judged` (flagged, never refused); `POST /beliefs` from a session refuses a compound statement (`belief_compound`, `atlas.beliefs.atomicity`: several sentences, a semicolon, "respectively", several periods) and one beyond its load-bearing quotes (`belief_beyond_quotes`; 503 `judge_unavailable` on an outage). The MCP tools return the refusals with their `detail`.
- Beliefs on the pages, from the pipeline and at the publish gate (atlas-beliefs ticket 03; `atlas.beliefs.exposure|pipeline|versions`): `GET /themes/{id}/map` and `GET /companies/{id}/dossier` gain `beliefs` (the theme's active Beliefs with `cited_companies`; the company's with its `exposure`: `holder` = the Belief names the company and its own load-bearing positive Fact backs it, `dependent` = it names the company but others' Facts carry it, `supplier` = it names another company and cites this one's Fact); `app/theme/` and `app/company/` lead with them (`components/beliefs.tsx` `BeliefSteps`). The argument plan's Editor task proposes one `unproven` Belief per kept step statement in the card's transaction (its Facts +0.5 load-bearing, the Skeptic Facts the counter-judge related to them by its valence map as context; produced by the `pipeline` session; the same statement in the same theme and step is cited again, not duplicated); the card's steps list `belief_ids`. Publishing a Hypothesis version records the active Beliefs citing an Assertion its findings rest on (`hypothesis_version_belief`, migration `0105`), the Research Snapshot carries them (`beliefs`, `belief_override`), and the publish gate refuses (422 `publish_gate_failed`, `belief_not_proven` with `belief_ids`) a version while a Belief it rests on load-bearingly is not `proven`, unless the request has `override_beliefs: true` and an `override_reason` (recorded in `hypothesis_belief_override` and the audit as `hypothesis.beliefs_overridden`).
- The Hypothesis page as the product (atlas-beliefs ticket 21; `atlas.theme_changes`): `GET /api/v1/themes/{id}/changes?limit=` is the theme's feed, newest first: Beliefs judged (not their proposal), flags and notices raised, Facts recorded (of a session or investigation of the theme, or cited by one of its Beliefs); each item has `kind` (`judged`, `flagged`, `notice`, `fact`), `at`, one line of `text` and the `belief_id`, or `fact_id` with `source_version_id`, it opens. `app/hypothesis/` leads with the thesis and whether it was checked, the steps, what is against them, the falsifiers, open Issues, predictions, calls made for it and the publish gate; the raw records are folded under "Records". `app/theme/` leads with the theme's Hypotheses (published first), then its Beliefs by step, then what changed.
- Research that compounds (atlas-beliefs ticket 26; migration `0112`; `docs/decisions.md`, "Research that compounds"): a session starts from what Atlas holds, not from nothing. `GET /api/v1/research/prior-work?theme=&as_of=&company_ids=&steps=&question=&exclude_session_id=&limit=` (`atlas.prior_work`; MCP `prior_work`, called right after `open_session`, the session's seeds by default) lists, bounded by the as-of time: the standing Facts for the companies and steps (newest document first, a cap and the count beyond it), the Beliefs of any judgement that name them or their steps (stalest first; who judged, `examined_through`), the documents earlier sessions read with those sessions' as-of times (`latest_session_as_of`), the earlier sessions with their cards' open questions, and the open Issues touching them (an Issue by its producing session's as-of time). `POST /facts` with a `session_id` for a span that overlaps a standing Fact of the same Source Version, company and step (`atlas.facts.reuse`) returns that Fact with 200 and `reused: true` when its status is the same and its statement the same (equal after case, whitespace and punctuation are normalised: `reuse.same_statement`, ticket 28; any other statement, a correction that drops a word included, is recorded and judged, `same_span_as` naming the first), recording nothing but a `session_fact_reuse` row (the session's `facts_reused`) and a `fact.reused` audit event; the MCP `record_fact` answers `recorded: false, reused: true`. `POST /beliefs/{id}/examine` (`{session_id, outcome: confirmed|qualified|contradicted|nothing_new, note?}`; MCP `examine_belief`) is an insert-only `belief_examination` and sets the Belief's `last_examined_at`, `last_examined_as_of` (the furthest of its sessions' as-of times) and `last_examined_outcome`, judging nothing; `GET /beliefs?sort=stalest` and the MCP `list_beliefs` (stalest by default) list never-examined Beliefs first, then the oldest `examined_through`, and the Skeptic routine takes the first proven one and reads only documents after it. A Fact a session recorded from a document newer than a proven Belief's as-of time, related `supports` to one of its load-bearing Facts by the counter-judge (`/statements/relate|judge`, `confirmed_beliefs`) or cited with the relation `supports`, gives it a `belief_confirmed` notice (`belief_notice`; `open_notices`, `notices`): not a flag, so it never counts in `open_flags`, the publish gate or proposed updates; only a judgement clears it; the Beliefs, theme and company pages show it beside the flags.
- The prospective record (atlas-beliefs ticket 19; migration `0113`; `atlas.calls`, `atlas.hypotheses.predictions`; `docs/decisions.md`, "The prospective record"; `docs/runbooks.md`, "Calls"): what Atlas said, dated, and what followed, insert-only. A **call** (`call_record`, `call_company` with each company's TradingView symbol from the theme config) is made in the transaction of a Belief judged `proven` (`origin` `belief`; direction `tightening` for `constraint` and `demand_vs_supply`, `easing` for `relief` and `invalidation`, else none), of a published Hypothesis version (`hypothesis`; the thesis, the Hypothesis's companies) and of a Scout session's `open_issue` of a `question` with the `lead_id` of an archive-signal lead (`signal`; the sentence, its company); dated by that event (the judgement's `at`, `published_at`, the Issue's `created_at`), never a request's date and never the session's as-of time; once per origin (and once per lead). `GET /api/v1/calls?theme=&origin=&state=&company_id=` reads them with companies, checkpoints and the next due date (`state` `open`, `settled`, `unpriced`). The daily `settle_calls` job (`ATLAS_SETTLE_CALLS_AT`, 05:30 UTC, backfill class; `uv run atlas calls settle` by hand; no LLM; a `tradingview` budget kind that is *not* failed while TradingView is off) first gives the Beliefs proven before this existed their call at their first `proven` judgement time, then appends for each call and horizon fallen due (+1, +3, +6 calendar months) one `call_checkpoint`: each call company's change in close from the call date to the due day (a day without a close takes the last, at most 7 days back), the change of the benchmark (the equal-weighted mean over the theme's researched companies that have a symbol, the call's own among them) and the difference, with the closes used; the closes come through the price service (`tradingview_price_bar`, the cross-process cap, `ATLAS_TRADINGVIEW_MAX_CALLS_PER_JOB`), a company not fetched defers the checkpoint (artifacts `deferred`), a call with no symbol, or TradingView off, records `call_unpriced` once (`no_symbol`, `tradingview_disabled`; not terminal: a later pass that can price it still appends). Closes score a call; they are never Evidence. **Predictions** (`prediction`, `prediction_settlement`): `POST /api/v1/hypotheses/{id}/predictions` (a published `version`, `measure` or the `prediction_index` of its `measurable_predictions`, `expected_low`/`expected_high`, `deadline` after the publication day, `source` `fact` | `financial_observation` | `price`, `company_id`), `POST .../predictions/{pid}/settle` (`fact_id`, `observation_id` or `day`; the value is read from the source, `met` inside the range else `missed`, `late` after the deadline; one settlement), `GET /api/v1/hypotheses/{id}/predictions` and `GET /api/v1/predictions?state=&hypothesis_status=` (`open`, `settled`, or `lapsed`: derived, never stored; rejected Hypotheses' stay listed); `settle_calls` also stores the closes of a price prediction past its deadline. Pages: the theme page's Calls panel (`frontend/components/calls.tsx`, `lib/calls.ts`) and the Hypothesis dossier's Predictions.
- The board (Chokepoint Watch ticket W1; spec `.scratch/atlas-watch/spec.md`; migration `0118`; `atlas.chokepoints`; `docs/decisions.md`, "The board is the fold of its events"): a `chokepoint` is one candidate bottleneck (theme, who made it); every change is an insert-only `chokepoint_event` (`created`, `field_set`, `step_set`, `status_set`, `note`; actor, session, run, payload, reason) and the current state is the fold of the events. `GET /api/v1/chokepoints?theme=&status=` (the latest event first; `status` is `lead`, `candidate`, `thesis_ready`, `killed` or `stale`), `POST /api/v1/chokepoints` (`theme`, `constraint`, `layer`, `holders`, `session_id?`, `run_id?`; 201), `GET /api/v1/chokepoints/{id}` (state and `history`), `POST /api/v1/chokepoints/{id}/events` (`kind`, `payload`, `reason?`, `session_id?`). State: constraint, layer, holders (`{name, slug?, cik?}`; outside the universe is fine), `status` as last set, six `steps` a to f (`unexamined`, `lead`, `primary`, `contradicted`, each with its evidence: `fact_ids`, `lead_ids`, `issue_ids`), `kill_criteria`, `relief_horizon` (`{horizon, basis}`), `crowding` (`early`, `emerging`, `consensus` or null; context, never evidence), `issue_ids` (set by `field_set`). `stale` is derived (no `field_set` or `step_set` event for 56 days, a note or a status change not counting; never for a killed one), not stored. `thesis_gate` `{holds, missing}` says whether `thesis_ready` would be allowed now, and a `thesis_ready` chokepoint whose gate no longer holds has `needs_review` (`?status=needs_review`); steps a, b and d of a `thesis_ready` chokepoint cannot leave `primary` until a `status_set` moves the status down (`thesis_ready_step_locked`; one event is one change). The steps are a constraint, b demand_vs_supply, c relief, d control, e capture, f invalidation (a payload names a step by letter or name). A list given in a payload (`holders`, `kill_criteria`, `issue_ids`, a step's `evidence`) replaces the whole list; `add_issue_ids` and `add_evidence` append. With a `session_id` (also on the reads) the session must be open, not isolated, of the chokepoint's theme (`other_theme`, as an Issue's must be) and of now (`not_prospective`: as-of more than 36 hours before now, the board being prospective); what it cites must have been public or opened by its as-of time (`created_after_as_of`; an Issue its own session opened is fine), a Fact of an isolated session is refused (`fact_not_in_session`), and the session's actor is the event's actor. A theme is a slug (`^[a-z][a-z0-9-]{1,40}$`); `run_id`/`created_by_run` refer to the `run` table, not a watch run. Refusals (422): `step_needs_fact` (`primary`/`contradicted`), `step_needs_lead` (`lead`), `reason_required` (`killed`), `thesis_not_ready` (`thesis_ready` needs steps a, b and d `primary`, a kill criterion and an open linked Issue; `detail.missing`), `fact_available_after_as_of` (a cited Fact public after the event's session's as-of time), `unknown_fact|lead|issue|session|run`, `isolated_session`, `invalid_payload`. Every write is audited (`chokepoint.created|updated`). `POST /api/v1/watch-runs` (`theme`, `run_date`, `mode` `architect`|`delta`, `memo` markdown, `counts`, `tool_calls?`, `cost_usd?`, `tokens?`, `session_id?`), `GET /api/v1/watch-runs?theme=&limit=` (newest first) and `GET /api/v1/watch-runs/{id}`: the Watch's insert-only run record (audited `watch_run.created`). MCP tools (`atlas.mcp.watch_tools`), each refused in an isolated session (`isolated_session`; the frozen surface of ticket 29, so the isolated prompt neither lists nor names them: `REFUSED_SERVER_SIDE_SINCE_0_6_14` in `tests/unit/test_agent_run.py`): `board(session_id, theme?, status?)` (the theme's chokepoints, steps as statuses, and the last memo), `get_chokepoint(session_id, id)`, `add_chokepoint(session_id, constraint, layer, holders?)` (in the session's theme), `update_chokepoint(session_id, id, kind, payload, reason?)`, `write_memo(session_id, mode, memo, counts?, cost_usd?, tokens?)` (records the `watch_run` for the session's theme dated the session's as-of day).
